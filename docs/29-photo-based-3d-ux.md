# 사진을 참고한 3분할 3D UX

## 최신 정정 · 지도만 3D, 카메라는 세 번째 패널 상단

2026-11-13 후속 사용자 정정: **3D 대상은 지도다. 건물 외관/카메라 영상을 3D로 바꾸라는 요청이 아니었다. 첫 번째 차량 정보는 기존 구성 그대로 유지한다.** 아래 최초 해석으로 만든 네 장은 이전 검토 기록이며 현재 설계 기준이 아니다.

- 첫 번째: 기존 차량 정보/차량 모형/주행 통계 구성 유지. 주변 상황/카메라 화면으로 교체하지 않는다.
- 두 번째: 기존 순정 내비 화면 구성 유지. 도착자리 카메라나 주차장 모델로 대체하지 않는다.
- 세 번째 상단: 빌트인캠 영상 영역만 배치. 카메라 사진 형태를 유지하고 문자 후보/관측 결과를 영상 우측 하단에 표시한다.
- 세 번째 하단: 주차 구획/통로/기둥과 엘리베이터·에스컬레이터를 읽는 **기울인 3D 지도**. 관측값과 시설 데이터 연결이 확인된 경우에만 위치/경로를 표시한다.

[정정 시안](ux/photo-based-3d/05-camera-and-3d-map.png) · [지시·출처·SHA256](ux/photo-based-3d/corrected-map-metadata.json). 기존 매장 기준 시안의 차량/내비 구성을 참고해 오른쪽만 재설계했다. 이미지 생성 편집이므로 바이트/픽셀까지 동일하다고 검증한 것은 아니다. 카메라 창은 공개 사진을 참고해 생성한 영상 형태의 예시이지 실제 빌트인캠을 연결한 화면이 아니다. 사진의2F/227은 관측 표현 예시이고 하단 주차장 배치/승강 위치는 개념도다. 현재 위치/거리/경로를 확정하지 않는다. 가운데 판교 지도는 기준 화면 보존을 위한 것으로 공항까지 이어진 실제 내비 장면이 아니다.

이 정정은 화면 구조 검토이며 앱/APK/DB/검증 수준은 변경하지 않았다. 아래의 건물 외관 중심 시안 설명은 후속 적용 지시로 사용하지 않는다.

## 이전 해석과 시안 기록

2026-11-13 UTC. 사용자가 요청한 방향은 사진 자체를 화면에 붙이는 대신 건물·차량·기둥을 차량의 주변 상황 표시처럼 단순화하는 것이다. [실제 사진 조사](28-real-place-photo-research.md)를 참고해 네 장의 **생성 디자인 시안**을 만들었다. 기존 시안/앱은 보존했다. [이미지 모음](ux/photo-based-3d/README.md) · [생성 지시·참고 사진·SHA-256](ux/photo-based-3d/metadata.json).

## 화면의 세 역할

| 영역 | 표현 | 책임 |
| --- | --- | --- |
| 왼쪽 약28% | 차량·주변 차·도로를 단순한 회색 입체로 표시 | 차량 시스템 영역을 가정한 맥락. 도착자리 앱이 제어/변경한다는 뜻은 아님 |
| 가운데 약30% | 어두운 지도·시설·내비 표시 | 순정 내비를 가정한 개념도. 실제 지도/위치/경로 데이터나 SDK 핀이 아님 |
| 오른쪽 약42% | 사진을 참고한 3D 장면·대상 강조·다음 행동 | 도착자리 서비스가 전달할 내용. 긴 설명 대신 한 장면/한 문장/두 버튼 |

상단 상태줄과 하단 공조/앱 도크는 전체 맥락을 보여주는 가정이다. 공식 Pleos 화면을 그대로 재현한 스크린샷이나 지원이 확인된 화면 삽입 규격이 아니다. 차량 시스템/내비/도착자리의 실제 분할 크기와 동시 실행은 접근 가능한 Pleos에서 따로 확인한다. 현재 화면은 모두 정차(P/0km/h)를 가정한다. 주행 중에는 요약과 음성 중심으로 줄이고 상세 조작 제한을 유지한다.

## 표현 원칙

회색 건물 면·간단한 차량·보도/차도 경계로 형태를 읽게 하고 목표만 얇은 파란 외곽선으로 강조한다. 학원 혼잡 예시는 주황색, 보행로 맥락은 청록색이다. 사진 질감/과한 발광/떠 있는 건물 모형을 줄였다. 다만 생성물에는 창문·바닥 등 세부 묘사가 남아 있어 실제 렌더러 제작 시 더 단순화할 수 있다.

건물 등 고정 구조는 공식 도면/사전 구축 자료와 연결할 후보이며, 차량·문자 표지 강조는 관측 표현 예시다. 하나의 사진에서 실측 3D 모델·자차 위치·숨은 연결 경로까지 얻었다는 뜻이 아니다. 모델/관측/안내가 각각 어떤 자료에서 나왔는지 구현 시 구분한다. 사진 참고 생성물은 최신 현장 사실을 증명하지 않는다.

## 장면별 의도와 경계

| 시안 | 참고한 실제 형태 | 보여줄 다음 행동 | 확인하지 않은 것 |
| --- | --- | --- | --- |
| 병원 | 분당서울대병원 암·뇌신경병원의 유리 입면과 낮은 갈색 캐노피 | 동행 조건을 확인하고 주차 안내 선택 | 강조한 캐노피는 입구 인지 방향의 표현이다. 특정 문/승하차 허용점·무단차/승강 연결은 확정하지 않음 |
| 학원 | 수내동 크리스탈빌딩 외관 | 건물 입구와 차량 만남 장소를 구분 | 셔틀/승용차 배치는 예시. 보도/도로 실제 치수·현재 혼잡·합법 대기 장소 미확인 |
| 정자역 | 실제 5번 출구의 경사진 유리 캐노피 | 사람 출구 확인 후 차량 승차 장소 찾기 | 5번 출구 자체가 차량 승차 허용점이라는 뜻이 아님. 지도/차량 배치는 예시 |
| 공항 | 인천공항 T1 장기주차 타워 내부와 사진의 2F/227 표지 | 문자 단서 확인 후 주차 기록에 저장 | 현재 위치·같은 번호의 고유성·터미널/승강기 연결 미확인. 지도 자차 화살표도 모형 위치 |

병원/학원/역의 가운데 지도는 지형 정확도를 검증하지 않은 개념도다. 공항 가운데 그림은 공식 T1 구역 관계를 단순화한 것으로 구획/도로를 측량한 지도가 아니다. 공항 장기주차 장면은 주차 단서 공통 기능이며 짧은 마중에 장기주차를 추천하는 결정이 아니다. 원본 사진의 게시/촬영일 미확인과 재사용 조건은 [출처 목록](research/real-place-references/README.md)을 따른다. 원본 외부 사진은 앱/저장소 배포 자산에 추가하지 않았다.

## 이후 적용 순서

1. 이 네 장에서 공간 단순화 수준·글자·강조색·행동 우선순위를 사용자와 검토한다. 매장 방문은 별도 대표 시나리오1로 유지한다.
2. 승인된 부분을 실제 도착자리 패널 하나의 레이아웃/상태 규격으로 바꾼다. 왼쪽 시스템/가운데 내비를 앱 안에 복제해 통합 성공처럼 만들지 않는다.
3. 시설 사전 자료/관측 후보/사용자 확인값을 구분해 기존 같은 방문 ID·저장 완료·닫기/재개 없음·설정/알림 복구 계약과 연결한다. 도면/측위 근거 없는 선·거리·엘리베이터 번호를 만들지 않는다.
4. Android 실행 화면과 Pleos 분할/SDK 결과/실제 핀·카메라 지원은 각각 따로 검증한다.

현재는 이미지4장과 문서만 변경했다. 앱0.9.0/9·e2b93ba·APK/서명/DB·기존 검증 수준은 그대로다. 새 빌드·기기 실행·카메라 처리·내비 연동·애니메이션 실행을 수행하지 않았다. docs08/12에 새 기능 성공으로 추가하지 않는다.
