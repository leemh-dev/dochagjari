# SDK 기반 아이디어 재선정

> 후속 확정: [운전자 교대 상태 비교43](43-driver-handover-concept.md)를 선택했다. 아래 휴식 경유 등은 이전 검토안이며 채택안이 아니다.

2026-11-14 UTC 사용자 결정: 카메라 접근에 의존하는 자동 주차 인식 방향을 중단하고, 공개 SDK로 구현 가능한 아이디어로 변경한다. 기존 코드/시안/영상을 삭제하지 않는다. 새 아이디어는 아직 사용자가 선택하지 않았다.

## 확인한 기능과 사용 가능 상태

- [공식 SDK 사용 신청](https://document.pleos.ai/docs/pleos-only/create-my-project): Vehicle State/NaviHelper는 신청 없이 사용 가능으로 안내한다. Vehicle Control/FusedLocation/TTS/STT는 준비 중으로 안내하므로 핵심 필수 기능에 넣지 않는다. 실제 프로젝트·차량별 상태도 대조해야 한다.
- [Vehicle SDK](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro): 문/좌석·주행거리/시간·배터리·연료 등 상태 조회 도메인, capability 조회·초기값·콜백을 제공한다. 도메인이 있다는 이유로 모든 차종/좌석/항목 지원을 보장하지 않는다.
- [NaviHelper](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro): 목적지/경유지 요청·경로/주행 이벤트·내비 화면 요청을 제공한다. 실제 콜백은 내비 구현/상태에 따라 달라지며 지도 embedding/자동3분할 지원으로 해석하지 않는다.

## 검토 후보 — 채택 아님

1. 동행 맞춤 휴식 경유: 사용자가 입력한 유아/어르신/반려동물 동행 요구와 이동 시간으로 쉴 시점을 제안하고, 조건이 확인된 사전DB 장소 중 사용자가 고른 경유지를 순정 내비에 요청. 졸음/건강/사람 역할을 센서로 추정하지 않는다. 시설 정보는 자체 관리 데이터이며 SDK 제공 정보가 아니다. 정확한 개별 API/권한·에뮬레이터 성공 확인 전 구현 확정하지 않는다.
2. 여러 사람의 승하차 일정 도우미: 사용자가 등록한 만남 장소/순서/시간과 내비 진행 정보를 연결해 다음 목적지 확인을 지원. 동승자 자동 신원인식/인도측 승하차 안전/정차 허용을 가정하지 않는다. 경유지 관리만으로는 기존 내비와 차별성이 약할 수 있다.
3. 출발·하차 확인 도우미: 지원되는 문/창/배터리 상태를 사용자 체크리스트와 연결해 놓친 항목을 안내. 제어 기능은 제외. 기존 차량 경고와 중복될 가능성이 커 우선순위가 낮다.

현재 추천 검토 대상은1번이나 기존 서비스 대비 차별성은 별도 조사 전 미확인이다. 새 아이디어의 전부가 SDK에서 제공된다는 뜻은 아니며 앱 로직/사용자 입력/검증된 소규모DB가 필요하다.

다음 순서는 후보→정확한API/권한/가용성 대조→Pleos 최소 실행으로 값/이벤트/내비 전달 확인→핵심 경험 확정→디자인/영상이다. 미확인 SDK 기능에 의존한 시연을 먼저 만들지 않는다. 현재 새로운 앱 구현/영상 제작은 하지 않았다.
