# 데이터 확보와 주차장 진입 후 카메라 관측 설계

2026-11-13 KST · 사용자가 추가한 서비스 방향/대응 방법. 설계 요구사항이며 데이터 제휴·실시간 검색·순정 카메라·자동 주차 위치 기록의 구현 완료 증거가 아니다. 실제 완료 수준은 [검증 기록](08-verification.md)을 따른다.

## 서비스 흐름

**실내 방문 목적 입력 → 최신 자료 조사/시설 지식 연결 → 진입 게이트·주차 구역·엘리베이터 추천 → 차량 내비 연결 → 주차장 진입 확인 → 주변 단서 관측 → 실제 주차 위치 확인·저장 → 목적지 방문과 귀환 안내**

몰·백화점을 기본 사례로 삼고 병원/아이 픽업/카시트/유모차/휠체어 조건으로 확장한다. 데이터가 부족한 항목은 확보 채널과 대체 동작을 설계해 해결한다. 목표는 기능 검증과 시연영상이며 실제 앱마켓 출시는 요구하지 않는다.

## 여러 경로로 시설 정보를 확보한다

| 채널 | 확보할 정보 | 처리/연결 방법 |
| --- | --- | --- |
| 공공데이터 | 시설/주차장 식별·위치·운영·규모 등 제공 필드 | 제공 기관 API/파일을 정규화해 시설·지점 식별자에 연결한다. 대표 좌표와 실제 차량 게이트 좌표를 구분한다 |
| 몰·백화점·병원 공식 사이트/시설 안내도 | 주차 게이트, 구역/층, 층별 매장, 엘리베이터/연결 층, 운영 제한 | 구조화 페이지·API·문서/도면을 읽어 연결 관계를 추출하고 도면 위치와 차량 진입점을 대조한다 |
| 최신 관련 리뷰·블로그 | 목적지별 접근 팁, 현장 변경, 혼잡/우회 경험 | 지점·매장·층이 맞는 최신 자료를 우선 검색하고 주장을 추출한다. 출처/시점/상충 여부와 함께 저장한다 |
| 시설·주차 운영사 제휴 | 공개 자료에 없는 구역/게이트 연결, 변경 공지, 가능한 주차 현황·위치 API | 필요한 필드를 제휴 항목으로 명시하고 제공 범위·갱신 주기·사용 조건·검증 상태를 관리한다 |
| 사용자 현장 확인 | 실제 이용한 게이트·주차 구역·엘리베이터, 잘못된 연결의 수정 | 자동 추출 결과를 보완하는 확인값으로 기록하고 적용 시설·시점을 구분한다 |

특정 출처 하나에 모든 정보를 요구하지 않는다. AI는 여러 출처의 시설/지점/층 이름을 매칭하고 관련 정보를 찾아 구조화한다. 출처를 확보하지 못한 항목을 임의로 채우지 않고 다음 채널의 확보 작업으로 연결한다. 제휴는 가능한 대응 경로이며 아직 체결/연동했다고 표시하지 않는다. 시설 데이터 제휴와 차량 플랫폼의 카메라 API/권한 승인은 별도다.

### 최신성·근거·커버리지

- 최신 관련 리뷰 우선은 기본 요구다. 게시일/수정일/수집일을 구분하고 해당 지점·목적지·층에 적용되는지 확인한다. 최근에 수집했다고 오래된 글을 최신 리뷰로 표시하지 않는다.
- 공식 변경 공지/최신 안내도와 리뷰를 함께 대조한다. 새 리뷰가 연결 변경을 주장하거나 자료가 상충하면 해당 연결을 재확인 대상으로 표시하고 이전 결론을 조용히 유지하지 않는다.
- 시설/실내 목적지/게이트/주차 구역/엘리베이터/보행 연결에 출처 URL 또는 제공자 ID, 정보 시점, 확인일, 확인 상태를 붙인다.
- 시설별로 `추천에 필요한 정보 확보`, `일부 정보 확보`, `갱신 필요`, `제휴/추가 확보 대상`을 표시한다. 실제 확보된 필드와 범위로 커버리지를 설명한다.
- 내부 연결이 일부 없으면 확인된 게이트·구역 안내와 미확인 구간을 구분해 제공한다. 운영시간·높이·필수 무단차 등 필수 조건은 미확인을 충족으로 처리하지 않는다.
- 정보 모델은 문장만 저장하지 않고 `시설 지점 ↔ 실내 목적지 ↔ 차량 게이트 ↔ 주차 구역/층 ↔ 엘리베이터 ↔ 보행 연결`로 구성한다. 추천 구역과 현재 빈 주차면은 별도 정보다.

## 내비 종료 이후를 관측으로 이어간다

내비는 검증한 차량 게이트까지 안내한다. 진입이 확인되면 지원되는 외부 카메라 입력을 통해 주차장 내부의 층·구역·기둥·벽 표기·엘리베이터 번호/방향 표지 등을 관측한다. 운전자가 별도 촬영 버튼을 반복 누르는 수고를 줄이는 것이 목표다.

### 상태와 기록 시점

1. **게이트 접근:** 추천한 시설/게이트와 계획 주차 구역·엘리베이터를 방문 세션에 연결한다.
2. **입차 확인:** 실제 도착/안내 종료 이벤트, 등록 게이트 접근, 차량 상태 등 확보 가능한 근거를 조합한다. 안내 취소나 경로 계산 완료를 입차로 오해하지 않는다. 현재 NaviHelper의 `onRoutingCompleted`는 경로 계산 완료이므로 입차 트리거로 사용하지 않는다. 지원되는 실제 도착 이벤트를 확인하고, 연결 전에는 명시한 테스트/수동 입차 입력을 제공한다.
3. **주변 관측:** 입차 후 제공되는 카메라 뷰에서 프레임을 표본 수집해 OCR/단서를 추출하고 시각·카메라 뷰·층/구역 문맥을 유지한다. 주행 중 운전자에게 영상 화면을 표시하지 않는다. 플랫폼이 허용하는 입력/백그라운드 범위만 사용한다.
4. **주차 후보:** 주행 중 잠깐 본 기둥을 최종 주차 위치로 확정하지 않는다. 지원 시 P/정차 유지 등의 실제 차량 신호와 최근 프레임을 조합한다. 신호 미연동 환경은 테스트 입력임을 표시한다. 이동이 재개되면 같은 방문의 관측을 이어가고 임시 후보를 갱신한다.
5. **위치 확인·저장:** 정차 부근의 최근 복수 프레임을 비교해 시설·주차장·층·구역·기둥/면 단서와 원본 근거를 묶고 필요한 경우 사용자에게 확인받는다. 관측/추정/사용자 확인을 구분한다.
6. **귀환:** 저장한 실제 주차 단서와 시설 연결 정보를 사용해 돌아갈 구역·층·엘리베이터를 안내한다. 계획한 엘리베이터, 카메라로 본 표지, 사용자가 실제 이용했다고 확인한 엘리베이터를 구분한다. 차량 카메라만으로 차에서 내린 사람의 보행 경로까지 관측했다고 주장하지 않는다.

### 단서가 부족할 때의 대체 동작

| 상황 | 동작 |
| --- | --- |
| 기둥 번호가 없고 벽/층/구역 표시는 있음 | 확보한 층·구역·벽 표기·방향 단서 범위까지 저장한다 |
| 표기가 흐리거나 같은 C12가 여러 층에 있음 | 복수 프레임과 최근 층/구역 문맥을 대조한다. 구분되지 않으면 확정하지 않고 확인을 요청한다 |
| 읽을 단서가 전혀 없음 | 정확한 주차 위치 미확인을 표시하고, 확인된 입차 게이트/마지막 단서와 수동 메모·사용자 사진 등으로 보완한다 |
| 제휴 시설이 위치 정보를 제공 | 허용된 운영사 API의 구역/위치 정보를 연결하고 카메라 관측과 출처를 구분한다 |
| 외부 카메라 SDK가 미지원/권한 미확보 | 공식 지원/정상 권한 경로를 조사하고, 사전 주차 영상·사용자 사진·테스트 프레임 입력으로 같은 분석/저장 흐름을 개발한다 |
| 플랫폼이 정차 중 카메라만 허용 | 허용된 정차 프레임과 기존 입차/시설 정보로 동작 범위를 유지하고 이동 중 관측을 검증했다고 표시하지 않는다 |

표시가 없는 주차장에서 AI가 기둥 번호나 정확한 주차면을 만들어내지 않는다. 실시간 실내 정밀측위가 없어도 확인된 층·구역·사진/단서와 귀환 계획을 제공하는 단계부터 구현한다.

## 구현 경계

- 카메라 입력 어댑터와 관측/저장 로직을 분리해 실제 SDK 프레임·사전 영상·수동 입력을 같은 파이프라인으로 검증한다. 순정 카메라 접근 경로/권한은 아직 미검증이다. 제약을 우회하거나 미공개 권한을 강제로 부여하지 않는다.
- 기존 OCR/영상 분석은 재사용 기반이다. 현재 C12 인식 성공을 입차 자동 감지·이동 중 연속 관측·최종 주차 위치 확정·귀환 완료로 계산하지 않는다.
- 주차 방문 기록에는 시설/실내 목적지/입차 게이트, 계획/확인 주차 위치, 엘리베이터 연결, 관측 시각/출처/근거/확인 상태를 둔다. 실제 방문 기록과 영상은 기기 내 최소 보관을 기본으로 하고 공개 증거는 명시적 테스트·비식별 자료로 남긴다.
- 프레임 표본 수집/해상도/보관량은 설정 가능하게 하고 실제 기기 부하를 측정한다. 아직 검증하지 않은 지속 촬영 성능을 보장하지 않는다.
- 주차 관측 갱신은 기존 SMS 발송 요청과 분리한다. pending/unknown 알림을 새 세션 재발송이나 DB 삭제로 해결하지 않으며 확정 요청의 동일 ID/내용 복구 규칙을 유지한다.

## 이번 검증/시연 우선순위

1. 실제 복합시설 한 곳의 목적지 두 곳과 필요한 연결 정보를 확보해 AI 자료 검색→추천 이유/근거→검증한 게이트 내비 전달을 보여준다. 사전 수집 자료를 쓰면 그렇게 표시한다.
2. 입차 이벤트→주차 영상 분석→정차 확인→실제 주차 단서 저장→귀환 안내의 같은 방문 흐름을 검증한다. 사전 영상/테스트 차량 신호와 실제 SDK를 구분한다.
3. 기둥/벽 표기가 있는 영상, 표기 없는 영상, 여러 층에 같은 번호가 나오는 영상, 관측 후 이동 재개를 시험한다. 틀린 확정보다 명시적 미확인/보완 동작을 검증한다.
4. 동행 조건 변경으로 추천이 바뀌는 병원/픽업/유모차·휠체어 사례는 이 기본 연결 구조의 확장으로 다룬다.
5. 전국 데이터 커버리지 확대·실제 제휴·모든 순정 카메라 지원을 제출 전 완료로 약속하지 않고 실제 확보/검증 범위를 기록한다. 목표는 검증된 기능과 시연영상이다.
