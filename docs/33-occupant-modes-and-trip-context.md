# 내비와 독립된 탑승 프리셋과 오늘의 탑승 구성

> 2026-11-14 최종 갱신: 앱0.11.0/11·f0640b0의 Cloud/일반Android 검사와90초 실행 편집본·20초 연속 모션을 완료했다. [현재 구현/검증37](37-current-implementation.md) · [영상/원본](evidence/demo-video/README.md) · [Mac 인계38](38-mac-pleos-v0.11-handoff.md). 아래 착수 당시 기획/이력과 실제 완료 수준을 구분한다. Mac/Pleos 실연동과 실제STT/외부카메라·실차는 미검증이다.



2026-11-13 UTC · 사용자 결정. 좌석별 주 이용자를 하나로 고정하지 않고 여러 구성을 저장한다. 이용할 때마다 다른 동승자는 음성·화면 선택·지원되는 좌석 센서를 함께 활용해 파악한다. **내비 목적지 입력과 별개인 공통 탑승 설정**으로 제공한다. 이번에는 기획/계약만 기록했으며 앱/APK를 구현 변경하지 않았다.

## 세 정보를 구분한다

| 정보 | 예 | 수명/책임 |
| --- | --- | --- |
| 저장한 탑승 프리셋 | 혼자 / 아이 등하원 / 가족 나들이 / 부모님 동행 / 사용자 이름의 구성 | 여러 개를 보관하고 좌석별 기본 역할·카시트·명시 이동조건을 사용자가 편집 |
| 오늘의 탑승 구성 | 이번에는 오른쪽 뒤에 아이, 왼쪽 뒤는 비어 있음 | 이번 탑승에서 확인한 값과 출처/시각. 내비 시작·목적지 변경과 독립 |
| 센서 점유 관측 | 왼쪽 뒤EMPTY, 오른쪽 뒤OCCUPIED, 미지원/UNKNOWN | 지원 좌석의 최신 관측. 사람의 나이·신원·건강·역할을 판정하는 데이터가 아님 |

‘오늘’은 하루 전체를 고정하는 뜻이 아니라 **이번 탑승**이다. 같은 날 혼자 출근했다가 아이를 데려올 수 있고, 같은 탑승으로 여러 목적지를 방문할 수 있다. 프리셋을 바꾸거나 이번 구성만 고쳐도 과거 방문·주차·알림 기록은 변경하지 않는다.

## 설정과 일반 사용 흐름

1. 공통 `탑승 설정`에서 프리셋을 추가/복제/수정하고 좌석별 주 이용 역할을 정한다. 설정 없이 사용/나중에 설정도 가능하다. 이름/나이/진단정보는 필수가 아니다.
2. 이번 탑승에서 짧은 음성 또는 모드 선택으로 구성을 알린다. “오늘 혼자야”, “오늘 아이랑 탔어”, “가족 나들이 모드” 등을 입력 방식의 예로 삼는다. 음성 SDK/호출 연결의 실제 지원은 별도 검증한다.
3. 지원 좌석의 점유와 저장한 프리셋을 비교해 후보를 고른다. **한 가지로 식별되지 않으면 짧게 확인**하고, 알 수 없는 좌석은 미확인으로 둔다. 단순 점유로 아이/환자라고 확정하지 않는다.
4. 확인한 경우 “오늘은 혼자 탑승으로 설정했어요”, “오늘은 아이 동반 구성이에요”처럼 짧게 알려준다. 매번 전체 설정창을 다시 채우거나 확인 모달을 반복하지 않게 한다. 인지/안내 제안은 건너뛰거나 끌 수 있다.
5. 이번만 바뀐 자리는 `이번 탑승만` 수정한다. 저장 프리셋 갱신은 별도 선택으로 제공해 일회성 탑승이 기본 구성을 덮어쓰지 않게 한다.

### 대화/제안 예시

| 입력/관측 | 제안/확인 | 결과 |
| --- | --- | --- |
| 사용자 “오늘 혼자야” | “혼자 탑승으로 설정했어요.” | 사용자 입력 출처의 이번 구성. 미확인 좌석은 센서EMPTY로 꾸미지 않음 |
| 사용자 “오늘 아이랑 탔어”, 저장된 아이 동반 프리셋이 하나 | “저장한 오른쪽 뒷좌석 구성으로 할까요?” | 짧은 확인 후 이번 역할/이동조건 적용 |
| 사용자 “아이 오른쪽 뒤에 탔어” | “오른쪽 뒷좌석, 아이 동반으로 설정했어요.” | 명시 좌석/역할 입력. 센서와 충돌하면 해당 자리만 확인 |
| 오른쪽 뒤OCCUPIED, 여러 프리셋이 같은 점유 | “오늘 탑승 구성을 선택해 주세요.” | 점유만으로 성인/아이 구분하지 않음 |
| 뒤 좌우EMPTY, 앞 동승석 관측 미지원 | 필요할 때 “뒷좌석은 비어 있어요. 이번 구성을 알려주세요.” | ‘혼자’를 자동 확정하지 않음. 미지원 상태 유지 |
| 이번 탑승에서 확인한 아이 동반 프리셋 + 같은 최신 점유 | 조용히 동일 상태 유지 | 같은 확인을 반복하지 않음 |
| 저장 프리셋의 아이 자리인데EMPTY | 해당 자리는이번에미탑승/확인전으로 분리 | 빈 좌석의 아이 조건을 이번 추천에 자동 적용하지 않음 |

센서가 카시트 물체를 점유로 보거나 늦게 갱신될 수 있으므로 관측값/사용자 역할을 따로 보관한다. 짧은 점유 흔들림으로 프리셋/탑승 세션을 새로 만들지 않는다. 값 안정화와 오래된 관측의 기준은 실제 SDK 특성을 확인해 구현 단계에서 정하고 확인 전 임의 신뢰도 수치를 만들지 않는다.

## 내비와의 관계

- 설정은 목적지가 없어도 열고 저장할 수 있다. 내비 시작/검색 때마다 좌석 설정을 다시 요구하지 않는다.
- 도착 안내는 사용자가 이번 탑승에서 확인한 구성의 필요한 이동조건을 읽는다. ‘아이’ 역할만으로 유모차, ‘성인’ 역할만으로 휠체어/돌봄 필요를 켜지 않는다. 프리셋에서 명시한 조건을 함께 적용할 수 있다.
- 내비/추천은 필요한 조건의 snapshot을 받는다. 추천이나 내비 요청이 프리셋을 수정하거나 센서 상태를 쓰지 않는다. 이번 탑승 구성 변경이 확정된 요청/발송 내용·수신자를 바꾸지 않는다.
- 좌석 모드 변경만으로 목적지를 바꾸거나 지도/관측/알림을 시작하지 않는다. 이미 확정된 방문/주차 기록/알림 세션은 보존한다.
- 별도 차량 OS 프로필/다른 앱 공유를 구현했다는 뜻은 아니다. 우선 도착자리 안에서 내비와 독립된 설정/상태로 설계한다. 클라우드 동기화·계정·실명 가족 인식은 이번 요청에 추가하지 않는다.

## 저장/복원과 현재 구현 보존

현재 구현은 [docs20](20-optional-seat-roles.md)의 단일 좌우 역할/카시트 선택과 DataStore 저장 완료·실패/순차쓰기다. `SeatPreferences.kt`의 역할은미지정/성인/어린이/영유아이며 점유는 별도다. 지금 확인된 SDK 좌석 범위는 뒤 좌우로, 앞좌석/다른 좌석의 지원을 구현 완료로 가정하지 않는다.

후속 구현은 기존 단일 구성을 기본 프리셋으로 이행할 수 있게 한다. 기존 DataStore 키/이동조건·방문UUID/자료snapshot·확정알림/outbox를 먼저 보존하며 실제 파일 이행은 구현/검사 후 완료로 표시한다. 프리셋저장과이번구성의확인은 UI변경/쓰기대기/저장완료/실패를구분한다. 저장실패가과거persisted를덮어쓰지않고이번만변경이기본프리셋을바꾸지않게한다.

재실행 때 저장한 프리셋을 복원하되 예전 센서값을 최신 관측처럼 되살리지 않는다. 이어지는 이번 구성의 출처/확인시각과 오래됨/미확인을 표시하고 새 관측/사용자 확인으로 갱신한다. 탑승세션은 방문ID/알림세션과 분리하며 차량시동/문이벤트 등 미확인 신호에 자동 의존하지 않는다. 새 탑승의 시작/종료 기준은 지원 신호와 명시 입력을 대조해 후속 구현에서 정한다.

주행 중에는 전체 좌석 편집/프리셋 생성 등 상세 조작을 제한한다. 음성/간단 확인도 공식 지원/주행 정책을 확인한 범위에서 제공한다. 설정 건너뛰기·역할 미확인은 기본 내비/도착 안내를 막지 않는다.

## 후속 구현/검증 기준

1. 프리셋 여러 개의 저장/수정/삭제·기본 구성 이행과 화면 없이 실제 저장값 재조회.
2. 혼자→아이동반→가족 구성 변경과 같은 날 여러 탑승, 같은 탑승의 여러 방문을 구분.
3. 음성의 역할/좌석 누락·모호함/취소·부분 변경·수동 입력, 역할과 점유 충돌/권한 없음/미지원/오래됨/카시트 물체 관측.
4. 연속 변경/저장 실패/즉시 종료/새PID에서 프리셋과 기존 설정/방문/알림 보존, 지난 센서값의 실시간 오표시 없음.
5. 이번만 변경/저장 프리셋 갱신을 구분하고 내비 시작/세션 발송/관측 자동재개가 없음을 확인.
6. 실제 SDK점유·TEST입력·음성 텍스트주입·실제STT를 따로 기록한다. 현재는 이 새 기능을 실행/검사하지 않았다.

## 시연영상 반영

[영상계획32](32-demo-video-production-plan.md)의 초반 탑승 조건은 내비의 필수 단계로 넣지 않는다. 미리 저장한 프리셋을 차량 이용 시 독립적으로 확인한 뒤 목적지를 요청하는3~5초 장면을 제안한다. “오늘은아이랑탔어”→이번아이동반구성확인→“에뜨와판교점에가자” 순서다. 센서만으로 아이를 판별하거나 모든 좌석 지원이 확인된 것처럼 표현하지 않는다. 일반 Android의 새 기능 구현/실제 음성/센서 녹화 전에는 UX컨셉으로 표시한다.
