## 내비와 독립된 탑승 설정

좌석별 주 이용 구성을 여러 프리셋으로 저장하고, 이용 때마다 음성·모드 선택·지원 좌석 점유를 함께 활용해 **이번 탑승 구성**을 확인한다. 혼자/아이 동반/가족/부모님 동행 등 사용자 구성이며 목적지 설정과 독립이다. 도착 안내는 확인한 이동조건을 읽는다. 점유만으로 아이/환자/신원을 식별하지 않고 기본 프리셋과 이번만 변경을 구분한다. [후속 설계33](33-occupant-modes-and-trip-context.md). 현재 앱의 단일 좌우 역할 저장 구현을 다중 프리셋 완료로 표시하지 않는다.

## 해결할 문제 · 장소와 도착

낯선 장소에 가는 운전자는 주소를 알아도 어떤 차량 입구로 들어가야 하는지, 사람은 어느 출구로 나오는지, 어디에서 기다리거나 승하차할 수 있는지, 어느 주차 구역과 승강시설이 목적지에 연결되는지 별도로 조사해야 한다. 매장 방문 때 블로그에서 주차 구역/엘리베이터를 찾던 사용자 경험이 출발점이다. 병원 진료동·학교/학원 문·역 출구·공항 터미널에서도 같은 연결 문제를 다룬다.

AI는 사전 DB의 확인 자료를 먼저 활용하고, 누락/변경 자료를 이동 중 조사·대조하는 역할이다. 공식 안내·리뷰의 내용과 실제 이용 조건/확인 시각을 구분한다. 사람이 이용하는 출구와 차량 진입점·승하차 허용점은 별도다. 시설 자료가 없으면 그럴듯한 입구 번호·승강기·거리·경로를 생성하지 않는다.

| 대표 이용 상황 | 제공할 계획 |
| --- | --- |
| 몰·백화점의 특정 매장/층을 방문하는 운전자 | 목적지와 연결되는 게이트·주차 구역·엘리베이터·보행 안내와 귀환 기록 |
| 병원 방문자/동행자 | 실제 진료 목적지와 하차/동반 주차·엘리베이터 연결 |
| 학교·학원 픽업 보호자 | 사람이 나오는 문과 차량 도착점·대체 주차·만남 위치 공유 |
| 낯선 역·공항에 마중 가는 운전자/도착하는 일행 | 터미널·도착층·출구와 확인된 승차점·대기 주차장을 연결하고 만남 단서 공유 |
| 카시트·유모차·휠체어 조건이 있는 이용자 | 저장한 동행/문 여유·차량 조건과 확인된 접근 가능 경로 적용 |

## 서비스 흐름

1. 방문/만남 목적과 지점·매장/진료동·출구/터미널 등 필요한 세부 목적지를 확인한다.
2. 공공데이터·시설 공식 안내·최신 관련 리뷰를 검색/대조하고 필요한 연결 정보를 구성한다. 공개 정보가 부족하면 운영사 제휴/현장 확인으로 채울 항목을 관리한다.
3. 상황에 따라 차량 진입→승하차/대기 또는 주차→승강시설/보행→최종 목적지/만남의 계획과 추천 이유·근거를 보여준다. 주차가 불필요한 픽업에 주차/승강 단계를 강제로 넣지 않는다.
4. 검증한 차량 진입점을 순정 내비로 전달한다. 막힌 지점은 같은 목적지의 대안 연결로 갱신한다.
5. 주차장 진입이 확인되면 지원되는 외부 카메라 입력으로 층·구역·기둥·벽/방향 표지를 관측한다. 주차 정차 부근의 단서를 확인해 실제 주차 위치를 저장한다.
6. 저장한 주차 단서와 확인된 엘리베이터/보행 연결을 귀환 안내에 사용한다. 단서가 없으면 정확한 위치를 만들어내지 않고 마지막 확인 정보·수동 보완을 제공한다.
7. 픽업에서는 동의/정차/확정 위치 조건에 따라 만남 알림으로 연결한다.

## 정보 확보와 카메라의 역할

공공데이터, 공식 사이트/도면, 최신 리뷰, 시설·주차 운영사 제휴를 조합해 커버리지를 늘린다. 게시/수정/수집 시점과 연결의 확인 상태를 기록한다. 제휴 추진과 실제 데이터 연동을 구분한다.

주차장 이후 관측은 내비 도착 안내와 최종 주차 위치 사이를 이어준다. 차량이 지나친 표기를 곧바로 최종 위치로 확정하지 않으며, 정차/이동 재개와 층 문맥을 반영한다. 순정 카메라가 미연동이어도 사전 영상·테스트 프레임으로 같은 파이프라인을 개발한다. 자세한 대응은 [데이터/주차 관측 설계](14-data-and-parking-observation.md)를 따른다.

좌석 점유는 저장 조건 제안의 보조 신호다. 탑승자의 카시트·휠체어 유무를 점유만으로 추정하지 않는다. 운전자용 카메라 영상은 주행 중 표시하지 않고 플랫폼의 정상 지원/권한 범위를 따른다.

## 검증과 시연 목표

현재 목표는 앱마켓 정식 출시가 아닌 기능 검증과 시연영상이다. 실제 복합시설 한 곳/실내 목적지 두 곳의 계획과 주차 관측/귀환 흐름부터 검증한다. 정보 출처·실제/가상 시설·실시간/사전 수집 자료·순정 카메라/사전 영상·실제 SDK/테스트 입력을 명시한다.

검색 시간, 실제 연결 정확성, 보행 부담, 잘못된 진입, 귀환 시 차 찾기를 수동 조사 방식과 비교한다. 아직 측정하지 않은 절감 수치나 전국 커버리지를 완료로 주장하지 않는다. 기존 동작 기반과 새 핵심 요구의 차이는 [구현 적합성 검토](13-product-fit-review.md)에 남긴다.
