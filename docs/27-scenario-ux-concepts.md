# 매장 외 시나리오 UX 예상도와 전환 규칙

2026-11-13 UTC. 사용자가 매장 시안에 이어 병원·픽업·역/공항의 디자인 예시를 요청했다. [docs26](26-service-continuation.md)의 네 대표 상황을 유지한다. 결과는 [시안 모음/PNG](ux/scenario-concepts/README.md)이며 Android/Pleos에서 구현·검증한 화면이 아니다. 시안은 정적이고 경로선 애니메이션을 새로 실행한 결과도 아니다.

## 공통 구성

- 왼쪽 시스템 주행 정보/차량뷰 + 중앙 순정 내비 모형 + 오른쪽 도착자리 보조 패널. 시스템 영역은 앱이 그리지 않는다. 플랫폼 분할 지원과 현재 개발 이미지/우리 앱 호환성·내비 내부 삽입은 구분한다.
- 어두운 중립색·읽기 쉬운 큰 한국어 산세리프·파란 주요 행동과 계획 경로·청록 보행 연결·황색 이용 불가/주의. 색만으로 구분하지 않고 텍스트/아이콘/실선·점선을 함께 쓴다.
- 오른쪽은 '목적/상태→기울인 공간 관계도→다음 행동' 순서다. 전체 안내를 긴 텍스트로 대체하지 않는다. 실제 기기에서는 앱 가용 폭과 폰트 확대에 따라 모드/정보를 조정해야 한다.
- 모든 생성 화면은 정차(P/0km/h) 상태다. 주행/상태 미확인에는 기존 상세·조작 제한을 유지하며, 정차로 복귀해도 관측/상세 지도/내비를 자동 재개하지 않는다. 실제 제한 동작은 기존 앱 증거와 별도다.
- 가상 병원/학원/역/공항은 실제 허용 승차점·무단차·도면·시설 규정을 확인한 장소가 아니다. 가상 선과 표식은 현재 위치나 실제 거리/승강기 번호를 뜻하지 않는다.

## 2. 병원 동행

[예상도](ux/scenario-concepts/02-hospital-companion.png): 휠체어 동행 조건, 기본 '함께 주차', 주차 구역→엘리베이터→진료동을 보여준다. 주 행동은 주차장 안내, 보조는 동행 조건이다.

구현할 전환 계약:

1. '계속 동행 필요'면 함께 주차하는 계획을 우선한다. 좌석 점유로 질환·역할을 추정하지 않는다.
2. '먼저 하차'는 확인된 허용 하차점과 동행 보호자 등 조건이 맞는 경우에만 제안한다. 먼저 하차 선택만으로 무단차/보호자 동행 조건이 충족되었다고 간주하지 않는다.
3. 차량 진입점→주차/승강 연결→진료 목적지를 확인한 자료로 구성한다. 자료가 부족하면 가상 시연/미확인을 표시한다.

실제 병원 접근성과 카메라/내비/좌석 연동을 새로 확인한 것은 아니다.

## 3. 학교·학원 픽업

[예상도](ux/scenario-concepts/03-academy-pickup.png): 황색 '승차점 이용 불가', 막힌 차량 접근점, 대체 P를 향하는 파란 차량 선, P→만날 문으로 이어지는 청록 보행선을 구분한다. '직접 데리러 가기'와 '주차장으로 변경'이 현재 행동이다.

구현할 전환 계약:

1. 바로 태우기·일찍 도착/대기·주차하고 직접 데리러 가기의 목적을 유지한다.
2. 막힘은 명시 사용자/TEST 또는 검증된 관측 출처를 따른다. 시안의 이용 불가를 현재 실시간 시설 정보로 사용하지 않는다.
3. 대체 후보가 있으면 정차 중 변경을 확인한다. 없으면 후보 없음으로 표시하며 사람이 이용하는 문으로 차량을 보내지 않는다. 보행선은 보호자가 이동하는 계획이지 아이의 단독 횡단 지시가 아니다.
4. 만남 위치 공유는 실제 정차·확정 단서·동의와 기존 알림 복구 계약을 따른다. 그림 속 공유 버튼은 실제 SMS 발송 증거가 아니다.

## 4A. 역 마중

[예상도](ux/scenario-concepts/04a-station-pickup.png): 사람이 나오는 출구, 차량이 가는 승차 구역, 대기 주차장을 나눈다. 파란 차량 경로와 청록 보행 경로가 만날 장소에서 연결된다. 주 행동은 승차 구역 안내, 보조는 만남 위치 공유다.

구현할 전환 계약:

1. 역과 출구를 확인하되 출구 번호와 승차 허용 구역을 동일시하지 않는다.
2. 일행이 준비되지 않았거나 현장 규정상 대기가 불가능하면 확인된 주차/대기 대안을 제안한다.
3. 열차/출구 변경·일행 위치는 실제 연동 또는 명시 입력이 있어야 갱신한다. 상태를 자동 생성하지 않는다.

## 4B. 공항 마중

[최종 예상도](ux/scenario-concepts/04b-airport-waiting.png): 터미널→도착층→만날 곳, '일행 이동 중' 상태, 주차장에서 끝나는 파란 차량 경로를 보여준다. 청록 보행선은 도착층→승차 구역의 계획이다. 주 행동은 대기 주차장 안내다.

구현할 전환 계약:

1. 공항·터미널·도착층을 확인한 뒤 승차 구역/대기 규정을 반영한다. 항공편 도착과 일행이 실제 승차 준비를 마친 것은 다른 사건이다.
2. 대기 중에는 주차장으로 안내한다. 일행 준비와 이용 가능한 승차 구역을 확인한 뒤 별도 사용자 선택으로 다음 내비 요청을 준비한다.
3. 항공편/일행 상태가 연동되지 않았으면 수동 확인으로 유지한다. 게이트 번호·도착 예측·법정 대기 시간을 추정하지 않는다.

초안의 파란 선이 승차 구역으로 향해 현재 대기 행동과 모순되는 것을 시각 검토에서 발견했다. 생성 이미지 수정으로 주차장에서 끝나는 선과 다음 단계 문구로 바로잡았다. 초안과 최종본을 같은 결과로 취급하지 않는다. 원본 SHA와 수정 이력은 시안 metadata에 기록한다.

## 저장·검증 수준과 다음 작업

네 최종 시안과 이전 승인 매장 기준 PNG를 저장했다. 도구가 만든 원본은 workspace에 남기고 복사본의 PNG 헤더/크기/SHA-256을 확인한다. 생성 글꼴 인상은 실제 폰트 파일/라이선스·Android 렌더링·터치 적합성 검증이 아니다.

이번에는 이미지/문서와 PR만 갱신하고 앱0.9.0/9·e2b93ba·DB/설정/알림/키/APK는 유지한다. JVM/기기/서버/실제 Pleos 검사를 반복하지 않는다. docs08/12의 기존 완료 수준도 올려 쓰지 않는다.

다음은 시안별 목적/상태/행동과 주행·정차·정보 부족·닫기 상태를 Android 규격으로 정리하는 것이다. 매장 시연을 먼저 적용하되 병원·픽업·역/공항의 선택 구조를 보존한다. 이 시안 저장이 임의의 순정 내비 조작·카메라 접근·외부 메시지 발송을 승인하거나 구현 완료로 표시하는 것은 아니다.
