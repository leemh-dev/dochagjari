# 4단계 · 시설 목적지 내비와 명시적 입차

2026-11-13 UTC · 기준 docs/07·17·18. 기존 방문ID/시설 snapshot·설정·알림 요청을 유지하고 목적지 요청→도로 내비 기록→명시적 입차→같은 방문의 네이티브 지도를 연결한다. 앱 후보0.6.0/6, 실제 결과는 검증 기록을 따른다.

## 근거와 목적지 구분

공식 판교점 위치/주차 안내 WC000000_V.do?branchCd=B00148000를 새로HTTP200조회했다. 판교역로146번길20,37.3927854/127.1120699는 공식 지도 마커·시설 대표 좌표다. 차량 게이트/정확한 진입점 근거가 아니며, 5층 보행좌표는 GPS가 아니다. [정제한 원문 근거](evidence/stage4-road-entry/official-facility-marker.json). 전체HTML/지도SDK키/무관한고객스크립트를 복제하지 않는다.

별도 road-target.json에 FACILITY_POI와 출처/확인일/자료 버전을 저장한다. 기존 visit-catalog 버전을 바꾸거나 과거 방문 자료를 덮어쓰지 않는다. 요청마다 목적지 snapshot을 방문 payload에 기록해 이후 자료 갱신이 기존 요청을 조용히 바꾸지 않게 한다. 현재 같은 방문의 명시적 재요청도 원래 목적지 snapshot을 유지하며, 새 자료 수용/계획 revision은 후속 단계다. 시설 목적지로 내비를 요청하며 차량 게이트/기둥·승강기 호기·거리/현재 위치를 만들지 않는다.

## 상태와 전달 계약

- VisitRecord JSON에 journey를 추가하고 없던 옛 레코드는 빈 요청/입차로 읽는다. SQLite schema/version·기존 식별 필드는 변경하지 않는다. 요청 ID와 입차 이벤트 ID는 방문 ID와 별개이며 SMS 세션을 새로 만들지 않는다.
- 방문 IO를 application-owned FIFO command queue로 직렬화한다. prepare로 목적지·방식/요청ID를 먼저 저장하고 claim을DISPATCHED로 저장한 뒤에만 SDK/모의 어댑터를 호출한다. 같은 요청의 동시 claim은 하나만 통과한다. 디스크 기록 실패는 외부 전달을 차단한다.
- DISPATCHED는 전달 구간 기록이다. 기록 직후 종료되면 실제 외부 전달 여부는 미확인이다. 재시작은 로드만 하며 자동 재요청/카메라/지도 재개를 하지 않는다. 사용자 취소·명시적 재요청은 같은 방문 안의 별도 요청ID로 이력을 보존한다. 요청 이력을 지우거나 SMS pending/unknown을 새세션/DB삭제로 복구하지 않는다.
- 모의 계산/SDK 함수 호출/SDK 콜백/순정 핀/입차를 구분한다. NaviHelper 콜백에 요청ID가 없어 이벤트 수신만으로 이 요청과의 일치·핀 성공을 확정하지 않는다. SDK 콜백/안내 종료를 입차로 바꾸지 않는다. 관련 없는 실제 목적지/차량 위치를 원본로그로 노출하지 않고 콜백 종류와 미검증 수준을 남긴다.
- '앱 내비 연결 취소'는 이 앱의 추적/요청을 취소한다. helper 해제는 순정 내비 경로 중지를 보장하지 않으므로 그렇게 표시하지 않는다. 취소/이전 요청의 늦은 이벤트는 현재 요청을 바꾸지 않는다.

## 입차/화면 계약

명시적 '직접 입차 확인·센서 감지 아님'(USER)과 '입차 테스트·실제 감지 아님'(TEST)을 제공한다. 테스트 입력은 테스트 차량 소스에서만 가능하다. 현재 실제 자동 입차 신호는 미연동이다.

정차 확인 상태에서 입차 이벤트 저장 성공 후 같은 방문을 PARKING_GUIDANCE로 바꾸고 기존 네이티브 5층 동선을 연다. 저장 중 차량 상태가 바뀌면 상세 지도를 열지 않는다. 주행/unknown에는 상세 지도·새 내비/입차/취소 조작을 제한한다. 실제 SDK 콜백 수신은 주행 중에도 기록할 수 있으나 상세 UI를 열지 않는다.

입차는 주차 완료/관측/측위가 아니다. 닫으면HIDDEN을저장하며 같은 입차의 반복/새 이벤트ID/앱재시작으로 다시 팝업하지 않는다. 수동5층동선보기는 기존 미리보기로 유지한다. 주차 관측/후보·주차확정/귀환은5~6단계다.
