# 방문 목적에 맞춘 주차·실내 동선 안내 — 요구사항과 현재 구현 검토

2026-11-13 KST · 검토 기준 d15907a · 사용자 요구 재정의/개선 제안. 구현 완료나 제출 범위 변경 확정 기록이 아니다.

## 사용자가 해결하려는 문제

몰·백화점 방문 전에 블로그·리뷰·시설 안내를 찾아 실제 방문할 매장/층에 가까운 차량 진입 게이트, 주차 구역, 엘리베이터를 고르고, 돌아올 때 차를 찾을 동선을 기억하는 수고를 줄인다. AI가 이 조사를 돕고 근거 있는 접근 계획을 만들어 차량 내비의 실제 진입점에 연결하는 것이 핵심이다. 병원·아이 픽업·카시트·휠체어는 이 기반의 방문 목적/이동 조건 확장이다.

서비스 정의: **건물 안의 실제 방문 목적에 맞춰 진입 게이트·주차 구역·엘리베이터·보행 동선을 연결하고, 귀환에 필요한 주차 위치와 경로를 기억하는 차량용 도착 계획 서비스.**

사용자는 정식 앱마켓 출시를 요구하지 않았다. 현재 목표는 기능 검증과 시연영상이다. 출시용 서명/마켓 등록을 필수 다음 작업으로 취급하지 않는다. 기존 개발 서명 APK와 제출 형식 요구사항은 구분한다.

## 냉정한 평가

- **사용 가치:**조사 시간이 들고 잘못된 게이트 선택 후 되돌리기 번거로운 복합시설에서 의미가 있다. 실제 방문 목적이 주차 선택에 영향을 주는 사례에 적합하다. 모든 단순 목적지에 같은 가치가 있다고 일반화하지 않는다.
- **차별성:**AI의 후기 요약만으로는 약하다. 지점/지점명/연결 관계를 검증하고 차량 내비 목적지와 귀환 기록까지 이어주는 것이 차별화 후보다. 주요 내비·시설 앱의 상세 기능을 전수 비교하지 않았으므로 독창성/시장 우위를 입증한 상태는 아니다.
- **가장 어려운 부분:**개발 화면보다 시설별 정확한 연결 정보, 진입 가능한 게이트 좌표/진입 방향, 운영시간, 엘리베이터 연결 층, 변경·폐쇄·후기 상충의 관리다. 검색된 글의 존재는 현재 경로의 정확성 증명이 아니다. 검색/수집/재사용 가능한 범위도 확인해야 한다.
- **AI의 역할:**자료를 찾아 지점과 연결 주장/출처를 구조화하고 사용자 목적과 연결한다. 실제 이동 연결이나 최적성을 임의로 만들어서는 안 된다. 확인한 사실·후기 기반 주장·미확인을 구분하고 근거 URL/확인일을 남긴다.
- **돌아오는 길:**주차장 입구와 실제 주차한 차 위치는 다르다. 시설·층·구역·기둥/면 단서와 이용한 엘리베이터를 사용자 확인과 함께 저장해야 한다. 현재 기둥 OCR을 귀환 안내 완성으로 계산하지 않는다. 실시간 실내 정밀측위는 별도 범위다.
- **확장:**유모차/휠체어는 확인된 전체 무단차 경로가 필요하다. 좌석 점유만으로 카시트·휠체어 유무를 판별할 수 없으므로 명시적 저장 조건을 기반으로 한다. 카메라/SMS/좌석은 핵심 도착 계획을 돕는 확장이고 정보를 찾는 기능을 대신하지 않는다.

현재 근거로 판단하면 문제 설정은 타당하고 제한된 시설에서 검증할 수 있다. 전국 임의 시설에 자동으로 정확한 추천을 제공한다는 주장은 현재 데이터/구현/검증으로 뒷받침되지 않는다. 절감 시간·경로 오류 감소·재이용 가치도 아직 실측 전이다.

## 검증/시연 중심의 개선 제안

1. 공식 층별 안내가 있고 확인 가능한 실제 복합시설 한 곳을 선정한다. 목적지별 접근 경로 차이가 있는 실내 목적지 두 곳으로 시작한다.
2. 시설/지점 식별자, 차량 게이트 좌표·방향, 주차 구역·층, 엘리베이터 ID/연결 층, 보행 연결, 운영·접근 조건, 출처/확인일을 구조화한다. 문장만 저장하지 않는다.
3. 방문할 매장/층을 입력하면 AI가 출처 있는 자료에서 관련 연결을 찾아 제안하도록 만든다. 사전 수집 자료 검색을 쓰면 그렇게 표시하고 실시간 웹 검색으로 시연하지 않는다.
4. 차량 접근과 주차 후 보행·층 이동, 사용자 조건을 함께 비교해 계획과 근거를 보여준다. 실내 정보가 없는 곳은 최적 추천을 주장하지 않는다. 추천 구역과 현재 빈 주차면도 구분한다.
5. 검증한 게이트 좌표를 내비로 전달해 실제 SDK 결과와 핀을 확인한다. 건물 대표 좌표나 보행 문을 차량 입구라고 간주하지 않는다.
6. 실제 주차 위치의 층/구역/기둥과 사용한 엘리베이터를 확인해 방문 세션에 저장하고 귀환 안내를 보여준다. 기존 카메라 OCR/저장 기반을 재사용할 수 있다.
7. 수동 검색과 AI 계획의 조사 시간, 실제 연결 정확성/도보 부담, 잘못된 진입, 귀환 시 차 찾기를 비교한다. 확인하지 않은 수치나 경쟁 우위를 만들지 않는다.

시연 이야기: **가상의 결과 문구 예시**로 “몰 5층 매장 방문 → 검증 자료에서 게이트/구역/엘리베이터 선택 → 차량 내비 연결 → 실제 주차 단서 확인 → 같은 엘리베이터를 이용한 귀환”을 구성할 수 있다. 게이트/층/기둥 번호 예시를 실제 시설의 검증된 안내로 오해하게 해서는 안 된다.

기존 앱의 차량 화면·내비 어댑터·옵션 저장·점유/OCR·알림 복구는 재사용할 수 있다. 다음 개발 우선순위는 목적지 식별/시설 지식 연결/근거 있는 계획/귀환이며, 이는 기존 docs/07의 픽업 중심 제출 범위와 달라지는 기획 제안이다. 이 검토만으로 docs/07이나 구현 완료 상태를 변경하지 않는다.
