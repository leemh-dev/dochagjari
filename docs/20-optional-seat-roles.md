# 3단계 · 선택적 좌석별 탑승 역할

2026-11-13 UTC · 기준 docs/07·17·18. 판교점 에뜨와 방문과 기존 프로필/방문ID/알림 복구를 보존한다. 앱 후보는0.5.0/5이며 최종 코드·APK 식별과 실제 검사는 증거를 따른다.

## 선택과 점유를 분리한다

- 현재 SDK에서 지원이 확인된 뒷좌석 좌·우를 대상으로 사용자 역할(미지정/성인/어린이/영유아)과 카시트 사용을 선택한다. 이름·생년월일을 요구하지 않으며 점유만으로 나이·신원·보조기구를 판정하지 않는다. 앞좌석/다른 좌석의 미확인 지원을 만들지 않는다.
- NOT_SET(미설정), CONFIGURED(저장한 역할 사용), SKIPPED(설정 없이 안내)를 구분한다. 설정하지 않거나 건너뛰어도 기존 매장/지도 안내가 가능하다. 역할 버튼을 고르면 CONFIGURED가 되고, 건너뛰기는 역할 사용만 중지하며 기존 선택과 이동 조건/방문 기록은 지우지 않는다. 다시 '저장한 역할 사용'으로 활성화할 수 있다.
- 좌우 점유 신호 EMPTY/OCCUPIED/UNKNOWN과 입력 출처는 기존 차량/테스트 UI를 유지한다. 최신 revision의 SAVED와 persisted가 확인된 CONFIGURED+OCCUPIED일 때만 저장한 역할/카시트 선택을 확인하라는 제안을 보인다. 편집 중/쓰기 실패/이전 revision 완료는 제안을 만들지 않는다. EMPTY/UNKNOWN이 역할을 지우거나 바꾸지 않는다.
- 역할만으로 유모차·휠체어·동행·문 여유 옵션을 자동으로 켜지 않는다. 기존 추천 조건은 별도 명시 선택을 유지한다. 주행/상태 미확인에는 역할·건너뛰기·재시도 조작도 막는다.

## 저장·이행과 데이터 보존

기존 profile.preferences_pb 파일과 여섯 키를 유지하고 seat_setup/좌우 role·child_seat/seat_schema=1 키만 같은 atomic edit에 추가한다. 옛 파일에 새 키가 없으면 NOT_SET/미지정/카시트false이며 기존 값과 다른 키는 보존한다. enum 문자열 미인식은 미지정으로 처리하며 점유로 대체하지 않는다. 기존 방문 SQLite·카탈로그·알림 저널/확정 요청 스키마는 변경하지 않는다.

화면의 선택값과 영속 저장 완료를 구분하는 기존 ProfileRepository의 순차 writer/revision/status를 재사용한다. SAVING 동안 바뀐 화면을 저장 성공으로 판단하지 않는다. 실패는 ERROR/이전 persisted를 유지하고 명시적 재시도로 같은 선택을 다시 쓴다. 저장값 재조회 API와 새 프로세스 검증으로 UI만 확인하는 검사를 피한다.

## 검사와 증거 기준

- 단위: 실제 DataStore 옛 파일 이행/다른 키 보존, 저장 직후 store 종료/새 인스턴스 복원, 알 수 없는 enum, 주입한 쓰기 실패 시 실제 파일/이전 persisted 유지·재시도; 순차/연속 저장 검사에 역할 포함. 순수 점유 제안의 경계 검사.
- 실제 기기: 역할/카시트 선택→저장 완료/저장값 재조회→건너뛰기→기존 설정/방문/알림 보존→Activity 재시작/안내 가능. 점유 변경이 역할을 바꾸지 않고 주행/unknown 쓰기를 막는지 확인.
- 별도 프로세스2단계: 모든 기존 이동 조건과 양쪽 역할/카시트를 저장하고 앱 종료·새PID에서 동일 값/동일 확정 알림 fingerprint를 검증한다.
- UI 원본22~25: 건너뛰기/역할 선택/테스트 점유 제안/재시작. 일반 Android 입력 성공은 Pleos SDK/Console/실차 성공이 아니다.

실제 결과/실패·해결은 [개발 일지](10-development-log.md), 최신 증거는 [3단계 폴더](evidence/stage3-seat-roles/README.md)에 남긴다. 백그라운드 AI 자료 보완은 docs/19의 후속 방향이며 이번 역할 설정에서 새 조회 worker를 구현하지 않는다.
