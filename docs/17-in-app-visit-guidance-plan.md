## 4단계 시설 목적지·내비·명시적 입차

[docs/21](21-road-navigation-and-entry.md)에 시설 대표 좌표와 차량 진입점의 구분, 같은 방문의 요청/전달/이벤트·명시적 입차와 닫기/복원 계약을 정했다. 실제 SDK/핀/입차와 일반 Android·모의 입력의 검증 수준은 docs/08을 따른다.

## 3단계 선택적 좌석 역할

지원이 확인된 뒷좌석 좌우의 명시적 역할·카시트 선택/건너뛰기와 저장 이행은 [docs/20](20-optional-seat-roles.md)을 따른다. 점유와 역할을 분리하고 기존 방문·설정·알림을 보존한다. 실제 로컬/기기 결과는 검증 기록에서 구분한다.

2026-11-13 UTC · 사용자가 확정한 다음 개발 계획. 이번 변경은 계획/기록이며 Kotlin·DB·APK를 구현/변경한 것은 아니다. 첫 대상은 **현대자동차 양재 사옥 출발 → 현대백화점 판교점 5층 에뜨와 → 주차 위치 기억·귀환**이다. [제출 기준](07-development-plan.md), [사전 DB](16-preloaded-db-and-indoor-route.md), [현재 검증](08-verification.md)을 함께 따른다.

## 2단계와 이동 중 자료 보완

네이티브 지도/파란선·재생/닫기와 사용자 추가 방향인 “이동 중 필요한 근거를 충분히 보완”하는 설계를 [docs/19](19-native-guide-and-enrichment.md)에 반영했다. 저장 DB를 먼저 사용하고 누락/오래된 자료는 백그라운드에서 조사·캐시하는 방향이며, 이번 단계에서 실제 AI 조회 worker를 구현한 것은 아니다. 앱 지도 구현/검사 결과와 기존 웹·호스트·기기 성공을 각각 구분한다.

## 목표와 첫 완료 기준

선택적 좌석 설정 → 목적지 요청 → Pleos 도로 안내 → 입차 확인 → 주차 안내 → 관측에 따른 경로 갱신 → 주차 완료 요약 → 화면 종료/귀환 기록을 **같은 Android 앱의 같은 방문 세션**으로 연결한다. [웹 미리보기](evidence/pangyo-scenario-preview/README.md)는 표현 참고이며 앱 성공 증거가 아니다.

첫 완료 APK는 실제 에뜨와/5F 데이터와 앱 내 2.5D 지도/파란 선, 명시적 테스트 입차·차량/관측 입력으로 전체 흐름을 동작시킨다. 영상/실제 SDK는 같은 인터페이스에 순서대로 연결한다. 테스트 입력·사전 영상이 실제 차량/카메라/음성 연동이라고 표시되지 않아야 한다.

## 상태 전환과 종료 규칙

`설정 건너뛰기/저장 → 목적지 선택 → 도로 안내 중 → 입차 확인 → 주차 안내/관측 → 주차 후보 → 위치 확인/저장 → 최종 요약 → 안내 종료`

- `GuideVisibility`는 방문 진행 상태와 별도다. 닫기 때문에 목적지/주차 기록이나 기존 SMS 요청이 삭제되지 않는다. 도로 내비 취소와 주차 화면 닫기도 분리한다.
- 입차는 지원되는 실제 도착 이벤트/게이트 접근·차량 상태 등 근거로 판정한다. 계산 완료·단순 안내 종료·취소는 입차 확정이 아니다. SDK 미연동/권한 미확보는 명시적 테스트/수동 입차 입력으로 연결한다.
- 순정 내비가 앞에 있는 동안 앱이 임의로 화면을 덮어쓰지 않는다. 정상 지원 인텐트/플랫폼 흐름을 확인하고, 자동 전환 불가 시 허용된 안내 진입점/사용자 선택으로 연다. 백그라운드 Activity/overlay 제한을 우회하지 않는다.
- 짧은 정차/P 미확인으로 주차 완료하지 않는다. 신호·정차 유지·최근 위치 단서로 후보를 만들고 신뢰도가 부족하면 확인을 요청한다. 실제 신호가 없으면 테스트 입력으로 표시한다.
- 주차 완료 시 기록을 먼저 저장한 뒤 요약을 보여준다. 기본8초(설정 가능한 초기값) 후 상세 애니메이션을 닫되 기록은 유지하고 다시 열 수 있다. 이동이 재개되면 같은 방문에서 주차 후보를 갱신한다.
- 사용자가 닫으면 해당 안내의 애니메이션과 카메라 관측을 중지하고 `dismissed`를 유지한다. 같은 입차/관측 이벤트로 화면을 다시 띄우지 않는다. 명시적 재개나 새 방문에만 연다.
- 앱 종료·백그라운드·권한 철회 시 관측 자원을 해제한다. 복원은 저장 상태/단서를 읽되 카메라·화면을 임의 자동 재개하지 않는다. 저장 실패는 완료로 표시하지 않고 재시도/미저장 상태를 제공한다.

## 지도·추정 안내의 표현

- 첫 구현은 **실제2D 도면의2.5D 표시**다. 가상의 입체 건물 형상을 사실로 만들지 않는다. 주차층→5층은 확인된 승강 연결의 층 카드/전환 애니메이션으로 표현한다. 주차층 도면/연결 미확인은 추정 요약/테스트 표시를 쓰며 정밀3D 경로로 위장하지 않는다.
- `기둥/구역 → 승강기 번호/ID → 주변 시설 설명` 순으로 확보한 식별자를 사용한다. 없는 번호는 만들지 않고 “유아휴게실·유아차 대여 쪽 엘리베이터”처럼 지도 단서에 근거한 추정 안내로 보완한다.
- 실제 위치 관측값이 시설 그래프와 연결될 때만 가까운 승강기 후보를 비교한다. 기둥 OCR만으로 존재하지 않는 거리/현재 위치·최적 경로를 계산하지 않는다. 연결 미확인은 현재 계획과 마지막 단서를 유지한다.
- 지도에 그려진 이동점은 **경로 재생 표시**다. 검증된 측위/위치 후보가 아닌 경우 실제 사용자가 그 점에 있다고 표시하지 않는다. 거리(m)/소요시간은 검증한 축척·측정 근거가 있을 때만 제공한다.
- 공식 지도/SDK가 웹에서 동작한 것과 앱 내 재사용 가능 범위는 별도다. 지도 인증 구성/DOM을 앱에 복사하지 않는다. 사용 가능한 도면 자산/연결 좌표를 확보하고, 필요하면 자체 개략도로 렌더러를 먼저 검증해 출처를 표시한다.

## 카메라 연결과 처리량

FrameSource는 테스트 관측, 사전 영상 프레임, 공식 지원 카메라 프레임을 구분한다. 프레임에 방문ID·출처·카메라 뷰·시각을 붙이고 분석 결과에는 인식 텍스트·층/구역/기둥 후보·신뢰도·확인 상태를 둔다. 선택 영상1회 분석 성공을 실제 연속 카메라 성공으로 계산하지 않는다.

- 초기 샘플링은1fps를 설정 가능한 출발값으로 삼고 기기에서 측정해 조정한다. 한 번에1작업/최신 프레임 우선/대기열 제한으로 뒤늦은 결과가 쌓이지 않게 한다. “실시간” 처리 성능을 측정 전 보장하지 않는다.
- 초기에는 최근3프레임 중2회 일치 같은 안정화 규칙을 후보로 구현/시험하고 실제 자료로 튜닝한다. 층 변경·승강 연결 모순/시간 만료 시 미확인으로 전환한다. 조건 변화 없는 중복 프레임으로 경로를 계속 재생하지 않는다.
- 같은 C12가 다른 층에 있을 때 층 문맥을 요구한다. C1~C3 구역 표기를 정확한 주차면/기둥 번호로 바꾸지 않는다. 문화센터5·6호기를 에뜨와 출구와 동일하다고 간주하지 않는다.
- 새 경로가 안정적으로 확인되면 짧게 전환하고, 사용자에게 후보가 흔들리는 화면을 반복 노출하지 않는다. 경로 불명확·카메라 미지원이면 저장 데이터/마지막 단서·수동 확인으로 계속한다.
- 실제 카메라 접근·정상 권한·제공 뷰·이동 중 사용 범위를 확인한 뒤 연결한다. 미지원이면 같은 Android 앱에서 사전 영상/테스트 관측으로 이어간다. 프레임 원본과 개인 주차 기록은 최소 보관하며 공개 증거는 테스트/정제 자료만 쓴다.

## 음성·차량 연동 경계

“플레오스에서 에뜨와 판교 현백 가자”가 앱 목적지 선택으로 전달되는 공식 음성/딥링크 경로를 조사한다. 해당 경로가 지원되면 동일한 목적지 resolver에 연결한다. 미지원이면 앱의 목적지 선택/텍스트 또는 명시한 음성 의도 테스트 입력으로 시연하고 Pleos 음성 통합 완료로 표시하지 않는다. 별칭 검색과 음성 인식/플랫폼 의도 전달을 별개로 검증한다.

선택적 좌석 프로필은 설정하지 않아도 일반 안내가 동작한다. 실제 점유 이벤트는 저장된 선호를 제안하는 보조 신호이며 탑승자 정체/카시트·장애 여부를 자동 식별하지 않는다. 기존 좌우SDK와 새 설정의 적용 좌석/미지원 상태를 각각 기록한다.
