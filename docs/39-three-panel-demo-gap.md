# 대표 시연의 3분할 구성과 실제 검증 구분

2026-11-14 UTC. 사용자가 GitHub 시연영상에3분할이 없다고 지적했다. 앞서 제공한90초/20초는 **일반Android에서 도착자리 앱 영역만 실행한 기능기록**이다. 이를 원하는 대표시연의 완료처럼 안내한 점을 바로잡는다.

| 산출물 | 현재 수준 |
| --- | --- |
| 기존 앱 단독90초 편집본/20초 연속 모션 | 실제 일반Android 앱 기능기록 완료. Pleos3분할이 아니다. |
| [새3분할20초 예상도](evidence/demo-video/three-panel-concept/README.md) | 첫 두 영역은 기존 생성 정지시안, 오른쪽은 실제 앱 녹화 일부 재배치. UX합성이며 실제 동시 실행 미검증. |
| 실제 Pleos3분할 대표시연 | **미완료.** Mac에서 실행한 순정내비/차량정보/앱을 같은 전체화면으로 녹화해야 한다. |

## 구성 기준

첫 번째는 차량 정보, 두 번째는 순정 내비, 세 번째는 도착자리다. 세 번째 상단만 카메라 입력/대체영상을 쓰고 하단에 기울인 주차/도로/5층 지도를 둔다. 카메라/건물 사진 자체를3D로 바꾸지 않는다. 기존 시안과 앱/APK를 보존한다.

## 실제 완료 기준

1. 공식 Pleos 환경에서 앱이 실제로 세 번째 영역에 배치되고 차량 정보/실행 중인 내비와 함께 유지되는지 확인한다. 런처/분할창 지원이 없으면 환경·패키지·창/서비스 상태와 원본을 기록하고 미완료로 둔다. 일반Android 창 크기480×900 성공으로 대체하지 않는다.
2. 같은 전체화면 녹화에서 에뜨와 목적지 요청과 SDK콜백/순정 핀을 각각 확인한다. 계산 완료를 입차로 처리하지 않는다.
3. 명시 입차→생성영상 관측/5층 파란선→주차 저장/닫기를 촬영한다. 원본은 전체3분할을 유지하고 세 번째 확대 컷은 보조자료로 구분한다.
4. Virtual Console 조작/SDK수신과 TEST 입력을 분리한다. 실제 카메라/실차를 확인하지 않았다면 표시를 유지한다. 개인정보·키·전화번호는 정제한다.

이번 Cloud 환경 상태조회는 cloud/running/connected와공유데스크톱 기능만 확인됐고 Mac원격/ADB 연결 경로는 제공되지 않았다. Mac을 실행했다고 주장하거나 Pleos를 근거 없이 재부팅하지 않았다. [M1/8GB·외장SSD 인계](38-mac-pleos-v0.11-handoff.md)의 첫 목표를 위 전체3분할 녹화로 보완한다.

이번 변경은 영상/문서뿐이다. 앱0.11.0/11·f0640b0, APK지문/서명, 기존CI 성공 수준, DB·설정·방문·알림을 그대로 유지한다. 합성을 새 기기검증으로 세지 않으며 통과한 앱 검사를 반복하지 않는다.
