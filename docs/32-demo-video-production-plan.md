### 주요 장면의 사실 경계

- 음성 “에뜨와 판교점에 가자”는 음성요청 UX 연출이다. 실제 Gleo→앱 호출을 녹화/검증하기 전에는 연결 성공처럼 표시하지 않는다. 실제 앱 기록에서는 현재 가능한 검색/터치를 사용한다.
- 사전DB 조회는 기존 구현 근거를 사용한다. **이동 중 AI 자료 보완 worker는 미구현 컨셉**이다. 이를 현재 앱의 백그라운드 실행 로그처럼 합성하지 않는다.
- 도로 내비는 접근 가능한 Pleos의 실제 녹화/SDK 결과/핀을 확보하면 해당 컷을 사용한다. 확보하지 못하면 본편의 화면을 계속 UX컨셉으로 표시한다. 경로 계산/도착 콜백을 입차로 처리하지 않는다.
- 주차 카메라는 사용 허용 원본 영상 또는 출처가 명확한 사전/생성 시연영상이다. 인천공항 사진의2F/227을 실제 판교점 카메라 입력으로 재표시하지 않는다. C12를 사용할 때는 생성 입력의 문자 후보이며 주차층/현재 위치 미확인으로 유지한다.
- 주차층/승강연결이 없으면 주차지도에 현재 위치 점이나 주차위치→엘리베이터 확정선을 만들지 않는다.5층 선은 기존 앱의 개략도/동선 미리보기 수준을 표시한다. 에뜨와/5층 입점 확인과 정확한 승강기/통로 연결 확인을 합치지 않는다.
- 귀환은 저장단서 조회이며 미확인 실내 측위/복귀선을 추가하지 않는다. 사용자 닫기 후 카메라·지도·내비가 자동으로 재개되는 연출을 넣지 않는다.
- 병원/학원/역/공항은 docs31의 개념도다. 병원 무단차/하차허용, 학원 실제 대안정차점, 역 승차점, 공항입국마중까지 확인됐다고 쓰지 않는다. 공항 컷은 출국 배웅이다.

## 애니메이션 연출

카메라 창은 짧은 영상 영역으로 유지하고 사진형 질감을 보존한다. 인식 테두리/결과 배지가 필요한 대상에만 나타난다. 미검증 카메라 시연에서는 영상 입력/인식 연출 여부를 장면 동안 표시한다. 실제 분석 녹화가 있으면 그 프레임/결과를 맞춰 쓰며 결과를 앞당겨 합성하지 않는다.

하단 지도는 도로/주차장/5층을 상황에 맞게 전환한다. 최초0.6~1초 동안 기울기/줌을 부드럽게 바꾸고, 파란선은4~6초에 걸쳐 펼친 뒤2~3초 멈춰 읽게 하는 것을 목표로 한다. 현재 앱의 실제 재생시간/FPS로 검증한 수치가 아니라 편집안이다. 새 컷의 벽/차도 횡단/선 연결과 라벨 충돌을 검토한다. 지도와 카메라를 함께 흔들거나 전체 화면을 과하게 줌하지 않는다.

첫 번째 차량 정보와 두 번째 내비는 각자의 역할을 유지한다. **오른쪽 서비스 패널이 변하는 것**이 시선의 중심이다. 도로 이동 중에는 서비스 요약/지도 맥락만 보여주고 운전자가 상세 메뉴를 조작하는 장면은 정차 상태에 둔다. 이번 시안의P/0km/h 정지 이미지를 속도/주행 상태가 실제로 변한 화면처럼 편집하지 않는다. 카메라 상세 표시는 현재 앱 주행 제한과 충돌하지 않게 정차 장면에 배치한다.

학원은 금지구간의 주황 강조 후 대안찾기 버튼으로, 병원은 함께주차/먼저하차 비교 후 선택상태로 전환한다. 역은 출구/보도만 표시하고 차로중앙 파란구역을 제거한 최종본을 사용한다. 공항은 승하차와긴대기/주차의 다른 목적을 보여준다.

## 제작 방식

**기본 제안: Remotion(React/TypeScript) + SVG/CSS 지도 레이어 + FFmpeg 출력.**

현재 생성PNG는 평면 이미지라 지도선/버튼/라벨을 각각 움직일 수 없다. 원본을 전체 줌하는 대신, 실제 편집 단계에서는 오른쪽 패널을 헤더·카메라·지도·선·상태·버튼 레이어로 다시 구성한다. 지도는 SVG와CSS기울기/얕은 입체로 시작한다. 자유로운 카메라/높이 변화가 꼭 필요할 때만3D렌더러를 추가한다. 먼저 단순한 지도 레이어로 가독성과 수정 용이성을 확보한다.

영상 전체를 AI생성영상으로 만들지 않는다. 고정된 UI는 코드로 배치해 글자/경계/지도선이 프레임마다 바뀌지 않게 하고, 사진형 카메라는 짧은 입력클립으로 넣는다. 나레이션·짧은 효과음·한국어 자막을 얹되 음성이 없어도 흐름을 읽을 수 있게 한다. 글꼴/음원/사진·영상은 제출에 사용 가능한 자료로 선택하고 출처/사용조건을 자산목록에 기록한다. 현재 참고사진 확보를 제출영상 재사용 허락으로 간주하지 않는다.

시연 소스는 앱과 분리한 `demo/video/` 경로를 후보로 한다. **아직 해당 코드/패키지/영상파일을 생성하지 않았다.** Remotion은 기본 제작 제안이며 라이선스/실행 환경은 실제 착수 시 확인한다. 렌더링은 가능한 Cloud/CI에서 수행하고 Mac M1/8GB에서 Android 에뮬레이터와 렌더러를 동시에 돌리는 것을 필수로 두지 않는다.

출력안은16:9,1080p/30fps,H.264/AAC,한국어SRT다. 목소리는 사용자 녹음 또는 일반적인 합성 나레이션 중 실제 제작 때 정한다. 특정인의 목소리를 흉내 내거나 Gleo가 실제 응답했다고 주장하지 않는다.

## 실제 앱 기록 · 약90초

본편과 구분한 파일을 기본으로 하고 제출 개수/용량 조건에 따라 본편 뒤의 명확한 `실제 앱 실행` 챕터로 붙일 수 있다. 통합해도 UX컨셉 표시를 지우거나 서로 다른 앱을 같은APK처럼 이어붙이지 않는다.

1. 녹화 환경/앱버전/코드와 TEST/MOCK를 밝히고 목적지/저장설정 확인.
2. 현재 가능한 목적지 요청과 명시TEST입차. 순정 내비 핀이 없으면 모의전달임을 유지.
3. 실제 Android 앱에서 출처표시된 생성/사전영상을 분석하고 문자후보/점유결과 확인.
4.5층개략도의 실제 파란선 재생을 녹화.
5.같은방문에서 명시주차완료→저장ACK/재조회→닫기→수동귀환기록 조회.
6.주행/상태미확인 시 상세조작 제한을 짧게 확인.

위 흐름은 **새로 확보할 원본 녹화 계획**이다. 기존PNG/CI결과를 이번에 녹화한 연속영상으로 간주하지 않는다. 원본은 가능한 한 같은APK/방문을 유지한 무편집 녹화로 보관하고, 본편 사용 시 시간 압축/장면 생략을 표시한다. SQLite/DataStore와방문ID 등 기술 추적은 공개정보를 정제한 별도 로그로 확인하고 제품 화면에 노출하지 않는다. SMS는 모의 발송/공급자 수락/실제수신을 분리하며 자격/동의 없는 실제 발송은 하지 않는다.

새 UX를 Android에 적용했다면 바뀐 소스를 먼저 검사한 뒤 해당 APK를 다시 녹화하고 버전/코드/SHA256/서명을 기록한다. 앱을 바꾸지 않으면 기존 검사를 새 수행으로 표시하지 않고 새 화면 녹화 사실만 추가한다. 실제 Pleos가 준비되지 않으면 일반 Android 녹화를 쓰고, Pleos 시스템 배경을 합성한 화면을 실제 실행이라고 표시하지 않는다.
