# 공모전 MVP 범위 및 제출 계획

## 11월 15일 1차 출품 범위

학원 픽업과 대체 경로, Pleos 좌석 점유, 병원 접근성 추천, 카메라 탐색, 자동 도착 알림을 함께 개발한다. 단계별 날짜, 승인·장비 조건, 확인할 증거는 [개발계획](07-development-plan.md)에 따른다.

| 기능 | 시연 기준 |
| --- | --- |
| 내비와 우회 | 같은 학원에서 픽업 모드 및 점유에 따라 차량 도착점이 달라진다. |
| 좌석 센서 | Virtual Console 입력에 앱의 좌석 상태와 저장 옵션 제안이 반응한다. |
| 병원 안내 | 유모차·휠체어·동행 조건에 맞춰 하차점이나 주차 구역이 달라진다. |
| 카메라 | 영상에서 점유·표지 단서를 분석한다. 사전 영상 사용 시 시연에 명시한다. |
| 자동 알림 | 정차와 위치 확인 후 사전 동의한 테스트 전화번호가 SMS를 받는다. |

전국 시설 확대, 면별 실시간 데이터, 실내 자동 측위와 자동 주차는 추가 개발 범위다.

## 데모 구성

| 장면 | 확인할 결과 |
| --- | --- |
| 같은 학원에서 픽업 방법 전환 | 차량이 가는 좌표만 달라지고 만날 문은 유지된다. |
| 정문 쪽 후보 이용 불가 | 대체 승하차점 또는 주차장으로 전환되고 경로 요청 결과를 확인할 수 있다. |
| 주차 후 상대에게 공유 | 추천 핀 대신 실제 정차 지점을 사용한다. 휴대폰에서 위치와 기준점을 확인할 수 있다. |
| 병원 접근성 옵션 변경 | 무단차 여부가 확인되지 않은 경로를 필수 조건 충족으로 보여주지 않는다. |

가상 시설, 사전 영상, 가상 차량 상태를 쓴 화면에는 시연용임을 표시한다. 에뮬레이터에서 동작한 내비 연동은 실제 요청 결과를 화면 녹화로 남긴다. 별도 시연으로 좌석 신호를 읽을 수 있는지 확인한다.

## GitHub 제출 준비

- 공개 저장소의 제출 커밋을 확정하고, 메일에 저장소 주소와 최종 커밋 해시를 적는다. 공식 안내에 따라 1차 발표일인 2026-11-23까지 공개 상태를 유지한다.
- APK를 제출할 때는 실행 가능한 release APK를 `apk/팀명_앱이름_release.apk`에 올린다. 용량을 초과하면 GitHub Releases 링크를 제출한다.
- 구현 후 루트 `README.md`에 앱 소개, 실행 방법, 테스트 환경과 설정, Pleos 에뮬레이터 버전과 화면 규격, APK 경로를 적는다.
- 제출 후보 커밋에서 설치, 앱 실행, 추천과 목적지 전달을 다시 검증한다. 공개 저장소에는 서명 키, API 비밀값, 개인정보 동의서 원본, 실제 아동 연락처와 이동 기록을 올리지 않는다.

1차 기획서에서는 차량특화성을 순정 내비·정차 맥락과 연결하고, 창의성은 상황에 따라 차량 도착점이 바뀌는 사례로 설명한다. 기술 활용성에는 실행 확인을 마친 SDK 범위를 기재하고, 사업성에는 학교·학원 반복 픽업 사용자와 시설별 데이터 확대 계획을 담는다.
