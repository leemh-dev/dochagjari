# 2단계 앱 지도와 이동 중 자료 보완 방향

2026-11-13 UTC · 양재 사옥→판교점 5층 에뜨와. [실행 단계](18-execution-stages.md)와 [앱 계획](17-in-app-visit-guidance-plan.md)을 따른다. 앱 0.4.0 / versionCode 4·수정 e573e8e의 일반 Android CI43358680681이 통과했다. [실제 앱 화면·APK 식별/검사](evidence/stage2-native-guide/README.md)를 따른다.

## 이번 구현 범위

저장된 방문에서 `5층 동선 보기`를 열면 Android Compose Canvas가 도형·문자와 경로를 직접 그린다. 기존 공식 보행 14개 좌표와 주변 매장 배치를 바탕으로 작성한 **5층 일부 개략도**다. 공식 지도 이미지를 앱에 복사하거나 웹 미리보기/지도 인증 구성을 WebView로 실행한 결과가 아니다.

`graphicsLayer`의 기울기/회전과 `PathMeasure`의 파란 선·이동점 재생을 같은 좌표계에 적용한다. 재생·일시정지·처음부터·평면/기울기 전환·닫기를 제공한다. 이동점은 동선을 보여주는 재생 표시이며 실내 현재 위치가 아니다. 기둥/호기·거리·전 구간 무단차를 새로 확인한 것으로 표시하지 않는다.

- 자료 버전/시설/층/출발·도착 식별자가 알려진 도면과 맞을 때만 렌더한다. 맞지 않으면 지도가 준비되지 않았다고 표시하고 방문을 보존한다.
- 기존 DB 스키마/자료 snapshot·방문 ID·설정·알림 요청은 보존한다. 같은 방문의 표시 상태만 VISIBLE/HIDDEN으로 갱신한다.
- 정차 확인 상태에서 명시적으로 연다. 주행/상태 미확인 또는 차량 입력 소스 변경 시 상세 지도를 닫는다. 앱을 다시 열어도 저장된 VISIBLE 값만으로 지도를 자동 팝업하지 않는다.
- 닫으면 Compose frame 작업을 취소한다. 앱이 background로 가면 재생을 일시정지하고, 시스템 동작 줄이기 설정이면 자동 재생하지 않는다. 버튼으로 명시적 재생은 가능하다.
- 도로 내비·입차 판정·외부 카메라 연속 관측·실내 측위·전체 귀환 안내는 이후 단계다. 이번에 구현했다고 표시하지 않는다.

## 검사/화면을 구분한다

1. 로컬 JVM에서 종횡비/뷰포트 정합, 자료 버전 불일치, 표시 상태 저장·복원을 검사한다.
2. 같은 Kotlin/Compose 화면을 Robolectric native graphics로 렌더하는 검사를 시도한다. 성공한 화면은 **호스트 Android framework/Compose 렌더**이며 에뮬레이터/Pleos 화면으로 표시하지 않는다.
3. 실제 일반 Android AVD에서는 중간 재생 프레임·일시정지·평면/기울기·닫기/복원과 주행 차단을 기기 검사한다. 원본 화면은 CI artifact에 보관한다.
4. Cloud에는 KVM/연결 기기가 없고 이전 Azure artifact 저장소 터널403이 있었다. 새 연결 근거 없이 같은 무가속 부팅/다운로드 실패를 반복하지 않는다. 화면 반입이 막히면 실제 원본 링크와 그 한계를 표시한다.

검사 중에는 실제 코드 컴파일 오류, 검사 의존성/렌더 환경 문제, 기기 실행 실패를 구분해 기록한다. 호스트 렌더나 웹 GIF 성공을 Android 기기/Pleos 성공으로 대체하지 않는다.

## 사용자 추가 방향: 주행 시간 동안 필요한 근거를 채운다

사전 DB로 빠르게 안내를 준비한 후, 출발부터 백화점 도착까지의 시간을 **필요한 자료를 충분히 확인하는 백그라운드 조사 시간**으로 활용한다. DB 우선은 유지하지만 “한 번 조회하고 끝”으로 제한하지 않는다. 이 절은 다음 단계 설계이며 이번 지도 구현에서 실제 AI/웹 조회 worker를 추가한 것은 아니다.

- **먼저 준비:** 저장 자료의 매장/층·게이트·주차/승강 연결·출처/확인일을 읽어 현재 가능한 계획을 만든다.
- **부족한 부분만 보완:** 누락·오래됨·출처 충돌을 조사 항목으로 잡고 공식 자료·최신 관련 리뷰를 찾아 대조한다. 이미 충분한 시설 자료를 같은 질문으로 반복 검색하지 않는다.
- **충분성 기준:** 목적지 식별과 추천에 필요한 연결, 필수 접근 조건, 출처/시점이 확인되면 해당 조사를 종료한다. 확인할 수 없는 항목은 미확인/추정 설명으로 남기며 근거 없이 번호를 채우지 않는다.
- **중복·처리량 관리:** 같은 시설/목적지 조사는 합치고 결과를 캐시한다. 시간/호출/비용 한도와 취소를 설정한다. 실제 도착 시각을 받으면 안내 전환 전 여유 시간을 고려하고, 없으면 설정한 작업 한도를 사용한다. 무한 반복을 “만족할 때까지”의 구현으로 삼지 않는다.
- **방문 기록 보존:** 수집 결과는 새 시설 snapshot으로 저장한다. 기존 방문 ID/원본 자료 버전을 조용히 덮어쓰지 않는다. 미래에 같은 방문에 별도의 계획 revision을 연결해, 호환/근거 확인 후 안전한 시점에 수용하도록 설계한다. 현재의 버전 불변 규칙을 깨지 않는다.
- **안정된 안내:** 자료가 조금 달라질 때마다 주행 중 화면을 흔들지 않는다. 경로 변경의 충분한 근거를 확인하고 주차 안내 전환/정차 등 안전한 시점에 안내한다. 입차 후에는 로컬 지도/관측 응답을 우선한다.
- **출처 표시:** DB 기반 계획, 조회/확인 중인 후보, 확인된 갱신, 추정 안내를 구분한다. 조사 실패가 기존 사용 가능한 계획·방문 기록·SMS 요청을 지우거나 새 세션 발송을 유발하지 않는다.

이 작업은 목적지·내비 연결 단계에서 준비를 시작하고 이후 관측/추천 갱신 단계와 연결한다. 데이터가 준비됐다는 가정으로 UI를 검증한 장면과 실제 자료 수집을 실행한 장면은 별도 증거로 남긴다.
