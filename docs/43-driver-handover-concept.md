2026-11-14 UTC 사용자 확정. 사용자는 새 후보 중 **차량 인수인계 영수증**을 선택했다. 배우자가 차를 이용할 때 경고등이나 설정 변화를 보고 차량 문제인지 물어보는 실제 상황을 출발점으로 삼는다. docs42의 이전 휴식 경유 추천안은 채택하지 않았다.

## 1차 경험

차량 안 앱에 운전자 별칭을 등록한다. 정차 상태에서 이번 운전자를 명시적으로 선택하고, 마지막 유효 기록과 현재 SDK 조회값을 비교한다. 차량이 사람의 신원을 자동으로 알아낸다고 가정하지 않는다. 소유자와 사용자 선택은 앱 내부 기능이며 Pleos 시스템 계정 연동을 구현했다는 뜻이 아니다.

교대 요약은 **차량 상태/경고 변화**, **조회 가능한 설정 변화**, **이전 사용자의 메모**를 구분한다. 기존부터 관측된 경고인지, 마지막 기록 이후 새로 관측됐는지와 각 관측시각을 보여준다. 첫 기록/수신 실패/미지원/오래된 값에는 비교 불가를 표시한다. 과거 기준과 달라졌다는 사실을 특정 운전자의 변경·고장 유발 증거로 쓰지 않는다.

SDK에서 실제로 조회 가능한 항목만 사용한다. 경고/연료·배터리/주행거리/공조 등은 개별 API·권한·capability·에뮬레이터 값을 먼저 확인할 후보이며 모두 사용 가능하다고 확정하지 않는다. 공식 설명서에 근거한 설명과 확인된 상태를 분리하고 운행 가능/고장 진단을 AI가 확정하지 않는다. 차량 제어/설정 자동 복원/차량 카메라는1차 필수 기능에서 제외한다.

출발 전 기록→사용 중 관측→명시적 사용 종료 기록→다음 운전자 확인으로 이어진다. 앱 종료나 관측 공백에는 기록이 없음을 표시하며 백그라운드에서 모든 변화를 놓치지 않는다고 약속하지 않는다. 차량/이전 사용자 기준과 해당 운전자의 지난 이용 기준은 별도 비교 축이다.

## 추가 아이디어 — 아직 채택하지 않음

- 경고 설명 카드: 현재 경고·지난 관측·공식 설명서의 권장 대응·사용자 메모를 한곳에 표시. 정비 진단 대체 아님.
- 다음 사람에게 한 줄: '주유 필요', '공조를 바꿨어요', '이 경고는 확인 중' 등 사용자가 직접 남기는 차량 내 인계 메모. 메모와 센서로 확인한 사실을 구분.
- 정비 상담용 변화 기록: 최초/반복 관측시각·주행거리·사용자 증상을 정리해 사용자가 선택해 내보내는 요약. 관측 공백/추정 인과를 명시.
- 낯선 내 차 안내: 이번 사용자가 헷갈리는 표시/기능을 공식 설명서와 차주가 작성한 안내로 설명. 알 수 없는 설정은 사용자 입력과 SDK 값을 구분.

다음은 경고/설정 후보의 정확한 SDK API·가용성 표와 최소 실행 검증이다. 기존 앱/영상은 보존하고 새 기능 구현 성공으로 세지 않는다. 신규 이름/화면/브랜치 분리는 구현 재개 시 정하며 기존PR은 자동 병합하지 않는다.
