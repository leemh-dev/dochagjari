# 도착자리 유지와 Pleos UX 고도화 방향

2026-11-13 UTC. 사용자가 대안 아이디어 탐색을 중단하고 도착자리를 계속 고도화하기로 결정했다. 기존 앱·방문 DB·설정·알림 복구를 보존한다. 제출 범위는 [docs/07](07-development-plan.md)의 기능 검증과 시연영상이며 앱마켓 출시는 요구하지 않는다.

## 서비스 정의

**방문·만남 목적과 동행 조건을 바탕으로 차량 접근·승하차·주차·최종 목적지까지의 이동을 연결하는 서비스.** 매장 방문은 대표 시나리오 1이며, 병원 동행과 학교·학원 픽업을 전체 범위에서 제외하지 않는다.

사용자가 블로그·공식 안내를 직접 찾아 주차 구역과 엘리베이터를 고르던 수고를 줄이는 것이 핵심이다. 기존 실내 지도 엔진을 새로 발명했다고 내세우지 않는다. 특허/유사 기능의 존재만으로 서비스 폐기나 목표 변경을 결정하지 않는다. AI나 화면의 화려함보다 확인한 자료로 이용자가 다음 행동을 이해할 수 있는지 평가한다.

## 경쟁 조사에서 확인한 것과 미확인인 것

- [현대오토에버 공식 자료](https://www.hyundai-autoever.com/kor/insight/archive/view.do?archiveSeq=9)는 실내 주차 지도·주차 위치·실시간 정보를 제공하며, 업체 발표로 2025년 12월 기준 167개 지점에서 운영한다고 설명한다. 이것을 현재 Pleos 특정 차종·판교점의 동일 서비스 운영 증거로 쓰지 않는다.
- [Parkopedia 제품](https://business.parkopedia.com/indoor-mapping)은 최종 목적지 기준 보행거리가 짧은 주차 공간 안내를 용도로 제시한다. 매장 기준 추천 자체의 세계 최초를 주장하지 않는다.
- 사용자가 원하는 특정 매장 검색→동행 조건에 맞춘 도착 계획→입차 후 카메라 층/기둥 관측→주차 지도/승강 연결→매장 동선의 전체 경험을 **현재 Pleos에서 상용 제공한다는 근거는 확보하지 못했다.** 검색 미발견은 부재의 증명이 아니다. 기존 순정 내비·연구·특허·시연과 현재 Pleos 운영을 구분한다.
- 따라서 기존 서비스와 비교하면서 도착자리의 연결 경험을 고도화한다. '경쟁자가 없어서 유효하다' 또는 '부분 기능이 있어서 불필요하다'고 단정하지 않는다. 설치 의향·재이용·현장 효용은 아직 사용자 검증 대상이다.

## 유지하는 전체 시나리오와 대표 시연

아래 순서는 기존 시나리오를 묶어 설명한 것이며 새 기능의 구현 완료나 11월 15일 제출 범위 확대를 뜻하지 않는다. 원래의 세부 상황은 [docs/02](02-service-scenarios.md), 기능별 실제 수준은 [docs/08](08-verification.md)을 따른다.

### 1. 매장 검색과 방문 안내

현대자동차 양재 사옥→현대백화점 판교점 5층 에뜨와를 유지한다. 출발지는 시나리오 기준이며 실제 기기 위치를 바꾸지 않는다. 사전 DB의 확인 자료를 먼저 사용하고, 누락/변경 자료는 이동 중 보완하는 방향을 유지한다. AI 자료 보완 worker는 현재 미구현이다.

확인된 차량 진입점과 시설 대표 목적지를 구분한다. 주차 구역→승강기→5층 연결이 확인된 부분만 안내한다. 앱의 기존 5층 기울인 지도·파란선은 매장행 미리보기이며 현재 위치 추적이 아니다.

### 2. 병원 방문과 동행

유모차·카시트·휠체어·계속 동행이 필요한 조건을 반영한다. 먼저 내려도 되는 동행자는 확인된 하차점과 운전자의 후속 주차를, 계속 동행해야 하는 경우는 함께 주차한 뒤 확인된 무단차/승강 연결을 안내한다. 실제 진료 목적지·허용 하차점·주차/승강 연결이 미확인이면 가상 병원 시연을 유지한다. 좌석 점유만으로 동행자의 상태나 역할을 판별하지 않는다.

### 3. 학교·학원 등하원과 픽업

사람이 나오는 문과 차량 도착점을 구분한다. 바로 태우기·일찍 도착해 대기·주차하고 직접 데리러 가기에 따라 확인된 접근점/주차 후보를 고르고, 막힌 후보는 대체점 또는 주차장으로 우회한다. 정차·동의·확정 위치가 갖춰진 경우 만남 알림을 연결한다. 모의 SMS·공급자 수락·실제 휴대폰 수신은 구분한다.

### 기존 확장 상황

역·공항 마중의 출구/터미널·대기 장소 선택도 docs/02의 확장 시나리오로 보존한다. 이번 결정으로 실제 시설 데이터나 외부 연동이 새로 완료된 것은 아니다.

## 여러 시나리오가 공유하는 기능

방문 자료 준비·순정 내비 연결·탑승 조건·막힌 지점 우회·주차 기억/귀환·만남 위치 공유는 공통 기능이다. 기존 UI 검토에서 별도 화면으로 그렸던 '주차 인식'을 병원 시나리오를 대체하는 시나리오 2로 고정하지 않는다.

### 주차 표지 관측과 주차 기억

공식 카메라 지원 전에는 출처가 보이는 영상·TEST 입력으로 관측을 이어간다. 정차 상태의 검토용 화면은 앱 패널 상단의 영상/관측 배지, 하단의 주차 지도/승강시설 관계로 구성한다. 실제 도면과 표지 연결이 없으면 가상 시연 또는 미확인으로 표시한다.

B2/B3·A03/A04 예시와 생성 C12를 실제 판교점 표지·위치로 승격하지 않는다. OCR 문자 후보와 위치 확정은 별개다. 주차 완료는 별도 확인/저장하며 닫기·주행·백그라운드·권한 철회·종료 후 자동으로 재개하지 않는다.

## Pleos 화면 구성과 지원 경계

[현대차그룹의 공식 Pleos 소개](https://www.hyundaimotorgroup.com/ko/story/pleos-connect-next-generation-infotainment-system)는 시스템 주행 정보 영역과 앱 영역, 두 앱 동시 분할 화면을 설명한다. 따라서 플랫폼의 분할 기능 자체를 미확인으로 남긴 이전 표현은 정정한다.

**시스템 주행 정보 + 순정 내비 + 도착자리 보조 패널**이 목표 구성이다. 앱이 시스템 주행 정보나 순정 내비를 복제하지 않는다. 이 양산 기능이 현재 개발용 이미지와 도착자리에서 같은 방식으로 동작하는지는 별도 실기 확인이 필요하다. 분할 지원은 지도 내부 overlay/층도 삽입·자동 확대·Gleo 서드파티 호출·카메라 프레임 접근의 근거가 아니다.

오른쪽 작은 패널 안에 기존 지도/카드의 이중 분할을 그대로 축소하지 않는다. 작은 패널은 핵심 정보와 주요 행동을, 확대한 앱은 지도와 자세한 안내를 담당하도록 설계한다. 글꼴은 한국어 가독성·층/기둥 숫자 구분·큰 터치 영역을 우선하고 실제 파일/라이선스와 Android 렌더링을 별도 확인한다. 그림 시안은 앱 실행 증거가 아니다.

## 고도화 순서와 완료 기준

1. **전체 흐름과 분할/확대 UX 규격**: 매장·병원·픽업의 다른 사용자 목표와 공통 기능을 구분한다. 우선 매장 시나리오로 보관한 공식 화면/검토 시안의 의미를 앱 규격으로 옮기되, 병원·픽업을 삭제하거나 매장 용어로 고정하지 않는다. 도로·입차 후 정차·관측·주차 저장의 정보 위계와 주행 제한을 정한다.
2. **판교점 자료 연결**: 확인된 자료와 빈 연결을 목록으로 나눈다. 근거가 확보된 주차/승강 연결만 채우고 미확인 번호·거리·좌표를 생성하지 않는다.
3. **Android 화면 고도화**: 기존 상태/저장 로직을 재사용해 작은 패널·확대 화면을 적용한다. 소스가 바뀌면 버전/APK 식별과 필요한 검사를 갱신한다.
4. **실제 Pleos 대조**: 접근 가능한 기기부터 확인한다. readiness와 개발 서명 대조 후 SDK 콜백·순정 핀·정상 분할/앱 전환·Console 수신을 각각 검증한다. 실패 근거 없이 Cloud 부팅을 반복하지 않는다.
5. **같은 APK의 연속 시연**: 목적지 선택부터 주차 기록까지 하나의 흐름으로 녹화한다. 실제/TEST·모의/영상·미확인 항목을 구분한다. 중간 앱 화면도 확보 즉시 공유한다.

이는 사업 범위의 무제한 확대가 아니다. 기존 ①DB~⑥주차/귀환의 일반 Android 검증은 보존하고, 현재 위치는 **⑦전체 시연 앞의 Pleos 화면/연결 경험 고도화 준비**다.
