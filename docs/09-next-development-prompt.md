이번 개발의 우선순위

1. 자동 알림의 종료·재시작 복구를 구현해줘.
   - 현재 앱 저널은 ID·상태·단서만 저장하고, 확인 좌표와 발송 대상·방식을 복원하지 못해.
     재시작 후 서버 결과를 조회하는 앱 경로도 없어. 코드를 확인하고 먼저 재현 테스트를 만들어줘.
   - 알림 상태를 표시 문자열과 분리하고, 같은 세션을 복원할 수 있는 확정 요청을 영속 저장해줘.
     세션 ID, 확인 위치·단서, 등록 수신자 ID, 발송 방식, 입력 출처와 동의 범위를 함께 묶어줘.
     실제 전화번호·API 토큰은 이 저널에 저장하지 말아줘.
   - 재시작 시 GET /v1/arrivals/{session_id}/{recipient_id}로 기존 결과를 대조해줘.
     서버가 404를 반환하고 기존 동의·요청이 유효할 때만 동일 ID·동일 내용으로 요청을 재개해줘.
     서버의 중복 제거를 유지하고, pending·unknown·조회 실패를 새 세션의 재발송으로 해결하지 마.
     공급자 호출 직전 서버가 종료된 경우도 결과 불명으로 남겨 중복 문자를 막아줘.
   - 모의 발송과 실제 SENS 복구 경로를 구분해줘. 재시작 후 토큰이 없으면 설정 필요 상태로 두고,
     이후 토큰 입력이나 결과 조회만으로 수신자·발송 방식을 임의 변경하지 말아줘.
   - 전송 전 종료, 서버 수락 후 응답 유실, 재시작, 반복 정차, 동시 요청, 수신자·위치 변경을 시험해줘.
     같은 세션에서 공급자 발송 시도는 최대 한 번이고 공급자 수락과 휴대폰 수신은 구분해야 해.

2. 프로필 저장 완료와 재시작 검증을 보완해줘.
   - 현재 화면 상태는 DataStore 저장보다 먼저 바뀌고 쓰기 작업은 ViewModel 수명에 묶여 있어.
     저장 직후 종료 시 누락 가능성을 재현하고, 저장 중·완료·실패를 구분해줘.
   - 좌석별 문 여유, 유모차·휠체어·동행, 차량 높이의 연속 변경이 순서대로 저장되게 해줘.
   - 기존 기기 테스트가 화면 값 변경만 보고 저장 완료라고 판단하지 않도록 수정해줘.
     실제 저장값 재조회, ViewModel 재생성, 가능한 환경의 프로세스 재시작으로 유지 여부를 검증해줘.

3. 실행 가능한 Android 환경에서 APK와 영상·UI를 검증해줘.
   - 연결된 기기와 Pleos AVD를 먼저 확인하고, 부팅 완료·package·activity 서비스 준비 후 설치해줘.
     접근 가능한 맥북 M1의 공식 Pleos 2.1.0/API 34 ARM64 AVD가 있으면 우선 사용해줘.
   - :app:connectedDebugAndroidTest를 실행하고, 픽업↔주차·우회·후보 없음·병원 동행,
     설정 저장·재실행·알림 복구·주행 중 조작 제한을 확인해줘.
   - 같은 앱에서 생성 빈 영상, 장애물·C12 영상, 공개 영상, 직접 선택 영상을 분석해줘.
     Android ML Kit의 C12 인식과 점유 결과에 따른 우회를 실제로 확인해줘.
     일반 영상에 빈 기준영상이 없으면 차량 미탐지만으로 EMPTY를 확정하지 말아줘.
   - 현재 분석 영역이 중앙 80%로 고정된 시연임을 유지 표시하고, 지점별 영역 설정과 저조도·가림
     처리는 후속 작업으로 기록해줘. 이번 복구 작업에 전국 시설 확대까지 추가하지 말아줘.

4. Pleos와 외부 연동은 환경이 준비되는 대로 이어서 검증해줘.
   - 공식 내비 샘플과 도착자리에서 두 접근점을 요청하고 SDK 결과와 순정 내비 핀을 각각 비교해줘.
   - Virtual Console의 뒷좌석 좌우를 Empty↔Occupied로 바꾸고 앱 초기값·콜백·옵션 제안을 확인해줘.
     Console 조작, 앱 수신, 실차 검증은 각각 구분해줘. 권한 거부·미지원도 시험해줘.
   - 실제 SMS는 서버 자격증명·등록 발신번호·동의한 테스트 수신자가 설정돼 있을 때만 검증해줘.
     준비되지 않았으면 모의 발송으로 계속 개발하고 실제 수신을 완료 처리하지 말아줘.
     비밀값을 채팅이나 GitHub에 요구하거나 기록하지 말아줘.
