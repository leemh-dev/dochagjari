# 다음 작업 — Android UX 검증 후 실제 Pleos/최종 시연

최신 디자인 정정: [3분할 UX 규격](29-photo-based-3d-ux.md)과 [정정 시안](ux/photo-based-3d/README.md)을 먼저 검토한다. **첫 번째 차량 정보와 두 번째 내비는 유지하고, 세 번째 상단만 빌트인캠 영상, 하단은 기울인 3D 주차 지도다. 3D 대상은 지도이지 카메라/건물 외관 영상이 아니다.** 이전 네 시안은 잘못된 해석 기록으로만 보존한다. 실제 통합 증거가 아니며 관측 후보·사용자 확인값/위치/경로를 구분한다. 기존 앱은 보존했으며 디자인 검토 후 적용한다.

2026-11-13 재개 결정: 아래 프롬프트의 기존 보존/검증 규칙에 더해 **[docs/26 도착자리 유지·고도화 방향](26-service-continuation.md)을 먼저 읽는다.** 대안 아이디어로 전환하지 않는다. 초행 장소·건물·주차장에 익숙하지 않은 사람을 핵심 대상으로, 매장 방문·병원 동행·학교/학원 픽업·역/공항 마중을 네 대표 시나리오로 다룬다. 주차 관측/기억은 공통 기능이다. 최종 녹화 전에 공식 Pleos의 작은 앱 패널/확대 화면에 맞춘 UX 규격과 자료 연결을 먼저 보완하되 대표 매장 시연으로 전체 범위를 축소하지 않는다. 플랫폼의 두 앱 분할 지원과 우리 앱의 실제 호환성·지도 내부 삽입·자동 표시·카메라 접근은 구분한다. 'Pleos에 동일 서비스가 없다'는 확정 표현을 쓰지 않는다. 현재 앱0.9.0/9·e2b93ba와 기존 APK 식별/검증 수준은 유지한다.

[Android UX 규격](25-android-navigation-ux.md) · [현행 결과/원본 화면·APK식별](evidence/android-product-ux/README.md). 아래 결과는 최신 GitHub/증거와 먼저 대조한다.

병원·픽업·역/공항의 [새 디자인 시안과 전환 규칙](27-scenario-ux-concepts.md)을 먼저 검토한다. 네 최종 생성 화면과 기존 매장 기준은 `docs/ux/scenario-concepts/`에 있으며 실제 앱/SDK 검증 증거가 아니다. 공항은 주차 대기 단계의 선이 주차장에서 끝나는 최종본을 사용한다.

후속 사용자 지적에 따라 [실제 장소 사진 조사](28-real-place-photo-research.md)를 디자인보다 먼저 대조한다. 병원·분당 학원가·인천공항 T1 장기주차장·정자역의 사진13장/공식 안내도2장을 로컬에 보관했고 GitHub에는 출처 목록을 남겼다. 생성 시설 도형을 실제 배치처럼 사용하지 않는다. 분당 학부모 승용차 픽업 대기 사진은 미확보이며 셔틀버스와 구분한다. 사진 재사용 조건·현재 시설/승차 규정·경로 연결은 별도 확인한다.
